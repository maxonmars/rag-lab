# 0003 — Первый RAG-запрос: поиск по индексу, режим RAG, контрольные вопросы

Статус: принято по плану задания «Первый RAG-запрос».
Дата: 2026-09-29.

## Контекст

Задание: вопрос → поиск релевантных чанков → склейка с вопросом → запрос к LLM; сравнить ответы без RAG и с RAG на
10 контрольных вопросах с ожиданием и источниками. Индекс (`index.json`, bge-m3, стратегии fixed и structure), Agent
и DeepSeek уже есть. Реранкинг, порог релевантности, цитаты, история и память входят в следующие задания.

## Варианты

Где искать: в ядре нужен был бы новый контракт поиска ради одной фичи; в фиче `rag` поиск использует её же индекс и
порт эмбеддингов, а `Agent` и `ModelPort` берёт из публичного входа ядра. Ядро и адаптер DeepSeek не меняются.
Хранилище: векторная БД (FAISS, sqlite-vec) окупается при тысячах векторов; в индексе несколько сотен чанков, поэтому
линейный перебор по косинусной близости читается целиком и не добавляет зависимостей.
Режимы ответа: только команда `rag ask` — нельзя сравнить, как одна и та же реплика REPL ведёт себя в двух режимах;
настройка `rag.enabled` — режим не меняется внутри сессии REPL, потому что настройки в REPL не изменяются;
переключатель `/rag on` и `/rag off` плюс `rag ask`, который всегда с RAG, — выбрано.
Формат контекста: `JSON.stringify` фрагментов противоречит правилу проекта «смысловой контекст — Markdown»; выбрано
Markdown с заголовками «Фрагмент N» и блоком кода с забором длиннее любой серии обратных кавычек в тексте чанка.
Формат вопросов: Markdown (`## qNN. Вопрос`, строки «Ожидание:» и «Источники:») читается и правится человеком;
YAML или JSON — структура ради структуры.
Оценка: LLM-судья — будущее задание и лишний недетерминированный слой; выбраны измеряемые показатели (попадание
ожидаемых файлов в top-K, ранг первого) и ручная оценка автора, отделённая от измерений.

## Решение

Фича `features/rag`: `search.ts` (косинус, `rankChunks`, `openIndex`), `context.ts` (Markdown-сообщение с
фрагментами), `prompts/answer.md` (инструкция режима RAG), `answer.ts` (`answerWithRag`), `questions.ts` (разбор
файла вопросов), `evaluation.ts` и `evalReport.ts` (прогон в двух режимах и отчёт `rag-eval.md`).

**Поиск.** Эмбеддинг вопроса той же моделью, что и индекс (проверяется digest); косинусная близость по чанкам одной
стратегии, по умолчанию `structure`; top-K, по умолчанию 5. Префиксы запроса не нужны: `bge-m3` их не требует.
Индекс читается один раз на объект `SearchIndex`: `rag ask` создаёт новый объект на каждый вызов, `rag eval` — один
на прогон.

**Режимы.** Оба режима используют один `app/system.md`; режим RAG добавляет `prompts/answer.md` и фрагменты в
сообщение пользователя. Единственное отличие режимов — найденный контекст. Режим сессии — локальная переменная
`ragMode` в `run()`; общего mutable-контекста нет. `ask` и обычная строка REPL следуют режиму, `rag ask` всегда с RAG.

**Настройки.** `rag.chunkStrategy` (`structure`), `rag.topK` (5, предел 20), `rag.questionsFile`.

**Контрольные вопросы и отчёт.** `experiments/feod-rag/questions.md`: 10 вопросов, у каждого ожидание и файлы-источники
корпуса; q10 — отрицательный контроль без источников. `rag eval` для каждого вопроса вызывает оба режима
последовательно; первая ошибка прерывает прогон и отчёт не пишется. Отчёт содержит найденные фрагменты, попадание
ожидаемых файлов и ответы обоих режимов; вердикты качества — ручная оценка в `experiments/feod-rag/README.md`.

## Последствия

`rag ask` и `rag eval` требуют запущенной Ollama с моделью индекса и ключа DeepSeek. Каждый `rag ask` читает индекс
целиком (единицы мегабайт). Попадание источника считается по файлу, а не по разделу. DeepSeek недетерминирован:
отчёт — один прогон, разброс не измерен. Ответ без RAG и с RAG различаются только контекстом, но не историей и не
цитатами: их нет в обоих режимах.

## Проверка

Тесты без сети: косинус и ранжирование, отказ при другой модели эмбеддингов, формат сообщения, разбор вопросов и
каждая причина ошибки, порядок вызовов и отчёт `rag eval`, команды через CLI и REPL. Ручной прогон —
[docs/demos/rag-query.md](../demos/rag-query.md), результаты — [experiments/feod-rag](../../experiments/feod-rag/README.md).
