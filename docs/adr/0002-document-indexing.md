# 0002 — Индексация документов: чанкинг, эмбеддинги Ollama, index.json

Статус: принято по плану задания «Индексация документов».
Дата: 2026-09-29.

## Контекст

Задание: взять набор документов (не меньше 20–30 страниц), разбить на чанки, получить эмбеддинги, сохранить индекс
с метаданными и сравнить две стратегии чанкинга — по фиксированному размеру и по структуре. Поиск, ответы с RAG,
реранкинг и цитаты входят в следующие задания.

## Варианты

Хранилище индекса: FAISS и sqlite-vec нужны при тысячах векторов и поиске; сейчас поиска нет, чанков порядка
сотен. Одна SQLite-база добавляет схему и миграции. Один JSON-файл читается человеком и `jq`, проверяется схемой.
Модель эмбеддингов: `nomic-embed-text` из лекции почти не работает на русском; облачные модели отправляют текст
корпуса во внешний сервис и требуют ключа; локальные модели Ollama бесплатны и приватны.
Размер: символы, токены или слова. Токенайзер модели недоступен без запроса к ней, поэтому размер — кодовые точки Unicode.

## Решение

Фича `features/rag`, команды `rag index` и `rag compare`, настройки `rag.*` в общем реестре.

**Корпус.** 32 русских документа feod-docs на коммите `f00eaf533cfee37f67e118c96291d535b0895a6f` (MIT), подготовка —
`npm run corpus:feod`. К файлу добавляется frontmatter с `source` (ссылка на файл закреплённого коммита) и `title`;
текст не меняется. Из текста для чанков frontmatter исключается, BOM и переводы строк нормализуются.

**Порт.** `EmbeddingPort` принадлежит фиче: `embed(texts)` возвращает векторы, `prompt_eval_count` и `load_duration`
пакета; `describeModel()` — имя и digest из `/api/tags`. Пакеты по 8 текстов последовательно, `truncate: false`,
без повторов. Число векторов, единая ненулевая размерность и конечность значений проверяются вне адаптера.
Адаптер Ollama не включает тело ответа провайдера в ошибки; по нему выбирается только код.

**Модель — `bge-m3`** (1,2 ГБ, 1024 измерения, контекст 8K, префиксы не нужны). Числа — nDCG@10 на русских задачах
поиска MTEB из [embeddings-benchmark/results](https://github.com/embeddings-benchmark/results); их опубликовали авторы
моделей, мы их не мерили, домен — новости и Википедия, а не техническая документация.

| Модель | Где запускается | RuBQ | RiaNews HN | MIRACL-ru HN | Belebele-ru |
|---|---|---|---|---|---|
| bge-m3 | Ollama, 8K | 71,2 | 84,1 | 70,3 | 94,7 |
| snowflake-arctic-embed2 | Ollama, 8K | 71,5 | 82,4 | 67,5 | 93,7 |
| embeddinggemma | Ollama, 2K | 69,7 | 80,3 | 64,5 | 95,1 |
| qwen3-embedding:0.6b | Ollama, 32K | 66,9 | 73,4 | 62,5 | 93,0 |
| jina-embeddings-v3 | API, лицензия CC-BY-NC | 72,3 | 81,3 | 65,4 | 93,1 |
| text-embedding-3-large | OpenAI API | 72,3 | — | — | 92,7 |
| nomic-embed-text v1.5 | Ollama, 2K | 5,5 | 18,8 | 13,6 | 31,5 |

`voyage-large-3` не существует: текущее поколение Voyage — voyage-4. `gte-base` знает только английский.
У Qwen3-Embedding выше средний балл MMTEB, но ниже результат на русском поиске и нужна инструкция в запросе.

**Чанкинг.** Единица измерения — кодовые точки; `text` чанка равен срезу нормализованного документа по `start`–`end`.
- `fixed`: окна `chunkSizeChars` с шагом `chunkSizeChars − overlapChars`, без сдвига границ к пробелам.
- `structure`: разбор Markdown в mdast (GFM), блоки верхнего уровня остаются целыми. Раздел начинается с каждого
  заголовка; чанк закрывается перед заголовком, если он не короче `minChunkChars`. Когда следующий блок не
  помещается, перекрытие из целых блоков (до `overlapChars`) переносится в следующий чанк, заголовок не остаётся
  последним блоком. Блок длиннее лимита делится окнами как в `fixed`; короткое начало раздела перед ним входит в
  первое окно. Чанк короче `minChunkChars` присоединяется к предыдущему, если вместе они не длиннее лимита.
  В корпусе 61% разделов короче 400 символов, поэтому без слияния получились бы сотни мелких чанков.
- `sections` чанка — пути заголовков (`Уровни › Уровень app › Назначение`) всех блоков, которых он касается.
- `chunk_id` = `<стратегия>:<файл>#<номер>-<8 знаков sha256 от хеша документа, стратегии, параметров и диапазона>`.

**Индекс.** Один `index.json`, `formatVersion: 1`: время, хеш корпуса, параметры, модель (имя, digest, размерность),
время загрузки модели, документы (текст и блоки — чтобы отчёт строился из одного файла) и чанки обеих стратегий с
эмбеддингами и метаданными. Собирается в памяти; запись — временный файл рядом и `rename`, ошибка оставляет прежний
файл целым.

**Сравнение.** `rag compare` читает индекс без модели и пишет `comparison.md`: размеры и число чанков, повторённый
текст, чанки на несколько разделов, блоки, не поместившиеся целиком ни в один чанк, токены, время и три участка для
ручного сравнения. Измеренное и вычисленное разделены: токены измерены на пакет, среднее на чанк — вычислено.

## Последствия

Для `rag index` нужны запущенная Ollama и скачанная модель; тесты работают без неё. Индекс — единицы мегабайт JSON;
поиск будущих заданий будет линейным перебором. Индекс не хранит модель для запросов: при смене модели или её
инструкции для запросов индекс пересобирается. Одиночный прогон времени не даёт разброса. Качество поиска не измерено.

## Проверка

Тесты: сохранность текста и покрытие, Unicode вне BMP, детерминированные ID, блоки не разрезаются, ошибки Ollama,
сохранность прежнего индекса при сбое, команды через CLI и REPL. Ручной прогон — docs/demos/indexing.md.
