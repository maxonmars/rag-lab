# 0009 — Локальная LLM как приватный сервис: шлюз с ключом и лимитами

Статус: принято по плану задания «Локальная LLM как сервис».
Дата: 2026-10-09.

## Контекст

Задание: развернуть локальную LLM как сервис с HTTP API и возможностью чата, проверить доступ по сети, стабильность при нескольких
запросах и базовые ограничения (rate limit, max context). Ollama слушает `127.0.0.1:11434`, не проверяет авторизацию, не ограничивает
частоту и молча обрезает вход сверх `num_ctx` (ADR 0007). Если открыть её в сеть через `OLLAMA_HOST`, любой клиент сети получит
модель без ключа и без лимитов.

## Варианты

- Только `OLLAMA_HOST=0.0.0.0`: нет ключа, лимитов и отказов по размеру контекста.
- nginx или caddy перед Ollama: ключ и rate limit есть, но лимит параллельности с очередью и лимит контекста по телу запроса
  требуют конфигурации, которой нет на машине (nginx, caddy не установлены), и не проверяются тестами репозитория.
- Node-шлюз `servers/llm-gateway` на `node:http`: все лимиты в коде, тесты с подменённым `fetch`, зависимостей нет. Выбран.

## Решение

Сервис — этот Mac как домашний сервер, модель `rag-local-opt` без изменений. Ollama остаётся на `127.0.0.1`, наружу смотрит только
шлюз (по умолчанию `0.0.0.0:8787`). Шлюз — отдельный workspace с собственным composition root (`src/app/main.ts` читает `GATEWAY_*`,
`compose.ts` связывает модули); `apps/` и другие серверы он не импортирует, host его не импортирует.

Контракт: `GET /health` без ключа, `GET /v1/models` и `POST /v1/chat/completions` с `Authorization: Bearer`. Порядок проверок чата:
ключ (401) → rate limit по ключу в скользящем окне 60 с (429, `Retry-After`) → тело ≤ 1 МиБ (413) и JSON (400) → поля запроса
(400: `messages`, `model`, `stream`, `max_tokens`, `tools`) → входной контекст в символах (413) → семафор с очередью (503,
`Retry-After`) → прокси в Ollama (502 и 504 при отказе и таймауте). Остальные пути — 404, эмбеддинги не проксируются.
Полная таблица и значения по умолчанию — [README шлюза](../../servers/llm-gateway/README.md).

Лимит контекста — сумма длин `content` в кодовых точках (`GATEWAY_MAX_INPUT_CHARS`), токенизатора нет. Значение по умолчанию
`32000` выбрано так, чтобы `prompt_tokens + GATEWAY_MAX_OUTPUT_TOKENS ≤ num_ctx (16384)`; проверка замером —
[experiments/feod-local-service](../../experiments/feod-local-service/README.md).

Host получает настройку `llm.localApiKey` (секрет, только env `LAB_LLM_LOCAL_API_KEY`); `LocalModel` отправляет её как Bearer, без неё —
прежнюю заглушку `local`. Ядро, `ModelPort`, фича rag и промпты не менялись. Ключи шлюза задаёт `GATEWAY_API_KEYS`
(`openssl rand -hex 32`), в логах они заменены порядковым id (`key1`).

## Последствия

- Только HTTP без TLS: ключ и тексты запросов идут открытым текстом внутри локальной сети. TLS, Tailscale и публичный доступ не входят в задание.
- Лимит контекста приблизителен: строка, плотная по токенам, даст больше токенов на символ, чем замеренный текст, и Ollama обрежет её молча.
- Состояние rate limit и очереди живёт в памяти одного процесса и теряется при перезапуске.
- Эмбеддинги берутся из локальной Ollama, поэтому RAG-режим rag-lab работает на машине с Ollama; с другого устройства доступны чат и `ask` без RAG.
- `stream: true` и `tools` отклоняются; один слот параллельности означает, что запросы ждут друг друга.
- Чат с длинной историей в `/rag on` может упереться в `GATEWAY_MAX_INPUT_CHARS` и получить 413; rag-lab это не обрабатывает отдельно.
