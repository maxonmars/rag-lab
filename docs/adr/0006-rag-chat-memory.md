# 0006 — RAG-чат: история диалога, память задачи, сценарии проверки

Статус: принято по плану задания «Мини-чат с RAG + памятью».
Дата: 2026-10-02.

## Контекст

Задание: CLI-чат хранит историю диалога, на каждый вопрос ищет контекст в базе через RAG и отвечает с учётом найденного, всегда
выводит источники. Усиление — «память задачи»: что пользователь уже уточнил, какие ограничения и термины зафиксированы, какова цель
диалога. Проверка — два длинных сценария по 10–15 сообщений: ассистент не теряет цель и продолжает отвечать с источниками.
До этого `Agent.respond` собирал `[system, user]` на каждый вызов и не принимал историю, а `rag ask` и режим `/rag on` отвечали на
одиночный вопрос (ADR 0003–0005). Поиск, rewrite, отбор по порогу, разбор цитат и «не знаю» уже есть и переиспользуются.

## Варианты

История: Markdown-раздел «История» внутри одного сообщения не расширяет ядро, но модель видит прошлые реплики как данные, а не как
собственный диалог, и путает их с фрагментами. Настоящие пары `user`/`assistant`, как в `my-first-agent`, требуют, чтобы `Agent`
принимал историю. Выбраны сообщения: это единственное изменение ядра, `Agent` остаётся без состояния, историю хранит и передаёт
вызывающий.
Хранение: файл сессии потребовал бы формата, версий и миграций; диалог нужен только внутри сеанса REPL. Выбрана память процесса,
хранилища не вводятся.
Обновление памяти: после ответа память отстаёт на один ход — rewrite и ответ не видят только что сказанного уточнения. Выбрано до
поиска, одним вызовом модели на ход, до rewrite и ответа. На вход — память и новое сообщение пользователя без ответа ассистента:
с последним обменом модель записывала в «Уточнения» утверждения документации из ответа как договорённости пользователя.
Номера `[N]` в истории: `N` — `rank` фрагмента из сообщения конкретного хода; в следующем ходу тот же номер указывает на другой
чанк. Ответы без `[N]` и без разделов модель копирует как образец: в прогонах это давало ответы без раздела «Ответ» или без
«Источников». Выбран полный формат ответа: `[N]` остаются, строка источника дополнена файлом и разделом, `chat.md` говорит,
что номера истории относятся к фрагментам своего хода.
Служебные блоки: память и фрагменты — Markdown-разделы текущего сообщения пользователя, `JSON.stringify` для смыслового контекста
не используется.

## Решение

**Ядро.** `DialogMessage = { role: "user" | "assistant"; content }` входит в `Message`; `respond(input, options)`, где
`RespondOptions = { tools?, history? }`. Порядок сообщений: system → история → текущий вопрос → раунды tool calls. Прежний вызов
`respond(input, toolSource)` заменён на `respond(input, { tools })`. `ModelPort`, `ModelRequest` и `ModelCompletion` не меняются;
адаптер DeepSeek отправляет assistant-текст как `{ role: "assistant", content }`, без `tool_calls`.

**Фича.** Чат — подкаталог `features/rag/chat/`, новая фича не создаётся. `chatTurn` не хранит состояние: принимает `Dialog`,
возвращает новый `Dialog`; ошибка любого шага отклоняет промис, нового диалога нет. Порядок хода: проверка параметров
(`checkRetrievalParams`, `rag.historyTurns`) → обновление памяти → rewrite (режимы `rewrite`, `rewrite-filter`) → `index.search` →
`selectForMode` → `generateAnswer`. До трёх вызовов модели на ход; при пустом отборе ответа модели нет, память при этом обновлена.

**Память задачи.** `TaskState = { goal, clarifications, constraints }`. Модель возвращает Markdown-разделы `## Цель`,
`## Уточнения`, `## Ограничения и термины` (`prompts/task-state.md`), пустое — «—». Если раздела «Цель» нет или он пуст, ответ не
разобран: прежнее состояние остаётся, `DialogTurn.stateUpdated` равен `false`. Память идёт моделям разделом «Память задачи» в
сообщении пользователя (rewrite, ответ, следующее обновление памяти).

**История.** В запрос ответа уходят последние `rag.historyTurns` ходов (по умолчанию 6, от 1 до 20) парами `user`/`assistant`;
rewrite дополнительно получает последние две реплики текстом. Реплика ассистента в истории — ответ в его формате: `## Ответ`,
`## Источники` строками `- [N] \`файл\` › раздел`, `## Цитаты`; отказ — `## Не знаю` и `## Уточнение`. `prompts/chat.md`
дополняет `answer.md`: история и память не источник фактов, пункт памяти, который влияет на ответ, называется в ответе явно.
`prompts/rewrite-chat.md` берёт из памяти только то, на что ссылается вопрос.

**Хранение.** Локальная переменная `dialog` в `run()` (`app/compose.ts`) рядом с `ragMode`; присваивается только после успешного
хода. `/rag off` диалог не сбрасывает, `/rag reset` сбрасывает. В CLI диалог живёт один запуск. `rag ask` и `ask` вне режима RAG
остаются одиночными.

**Команды и настройки.** `/rag on` включает чат; под ответом чата — цель и пункты памяти, добавленные этим ходом
(`Память: добавлено` или `Память: без изменений`). `rag state` показывает память, `rag reset` сбрасывает диалог, `rag dialog` прогоняет
сценарии. Настройки `rag.historyTurns` и `rag.dialogFile`.

**Сценарии и метрики.** Файл `experiments/feod-chat/scenarios.md`: раздел `## sN. Название`, поля «Цель:», «Ключи цели:», «Память:»
(`- N: ключ` — ключ задан в реплике N), нумерованные «Реплики:». Каждый сценарий идёт в новом пустом диалоге. Цель сохранена на ходу,
если каждый ключ цели — подстрока нормализованной цели из памяти; ключ памяти удержан на ходах с номера N, если он подстрока
нормализованной памяти. Остальные метрики — разобранные ответы (источники, дословные цитаты, «не знаю», замечания) и ходы с
неразобранной памятью. Отчёт `rag-dialog.md` пишется один раз после успеха; первая ошибка прерывает прогон.

## Последствия

- Ход стоит на один-два вызова модели больше, чем `rag ask`: память и, в режимах с rewrite, переписывание запроса.
- Память зависит от модели: она может записать в «Уточнения» пересказ вопроса. Метрика ключей этого не замечает — только ручная
  оценка (README эксперимента). Согласие пользователя с предложением ассистента («да, так и сделаем») память не раскрывает:
  ответа ассистента она не видит, условие пользователь называет сам.
- Нарушение формата памяти оставляет прежнее состояние и видно в отчёте (`stateUpdated`); повторного вызова нет.
- Метрика цели — подстрока ключей, а не смысл; «цель сохранена» не доказывает, что ответ ей следует.
- Rewrite с памятью может вопреки промпту добавить в запрос цель или ограничения диалога и увести поиск от темы вопроса; в
  `baseline` и `filter` follow-up с местоимением ищется по исходной формулировке, без памяти и истории.
- История в полном формате длиннее: с цитатами прошлых ходов растёт размер запроса ответа.
- Диалог теряется при выходе из REPL; окно истории обрезает старые ходы, память хранит из них только сказанное пользователем.
- Один прогон, DeepSeek недетерминирован; токены и стоимость не считаются: `ModelPort` их не возвращает.

## Проверка

Тесты без сети: история в запросе `Agent` и в wire-формате DeepSeek; разбор и рендер памяти; окно истории и текст ответа ассистента
для каждого вида `CitedAnswer`; порядок и число вызовов модели в `chatTurn` по режимам, пустой отбор, неразобранная память, ошибка
шага; формат сценариев и каждая причина `SCENARIOS_INVALID`; метрики и отчёт `rag dialog`, сохранность прежнего отчёта; REPL-сеанс:
история во втором ходу, `/rag state`, `/rag reset`, независимость `/rag ask`, ошибка посреди хода. Ручной прогон —
[docs/demos/rag-chat.md](../demos/rag-chat.md), результаты — [experiments/feod-chat](../../experiments/feod-chat/README.md).
