# Первый RAG-запрос: ответ без RAG и с RAG

Цель: показать, как вопрос превращается в запрос к DeepSeek с найденными фрагментами документации, и чем ответ с RAG
отличается от ответа без него. Решение — [ADR 0003](../adr/0003-first-rag-query.md), контрольные вопросы и результаты —
[experiments/feod-rag](../../experiments/feod-rag/README.md).

## Требования

- индекс из [демо индексации](indexing.md): `npm run corpus:feod`, затем `npm run dev -- rag index`;
- запущенная Ollama (`ollama serve`) и та же модель, что при построении индекса (`bge-m3`): при другом digest поиск отказывается работать;
- `LAB_LLM_API_KEY` в корневом `.env` или окружении процесса; значение нигде не печатается.

## Сценарий

1. Ответ с RAG одной командой. Под ответом печатаются найденные фрагменты: ранг, файл, первый раздел, сходство.

```sh
npm run dev -- rag ask "Что можно хранить в global?"
```

Ожидается блок `── Ответ агента · RAG ──`: текст ответа, пустая строка и `Фрагменты:` со строками вида
`1. structure/global.md › Global › Правило · 0.71`. Суффикс `(+N)` означает, что чанк касается ещё N разделов.
Число строк равно `rag.topK` (5); текст и сходство зависят от прогона.

2. Тот же вопрос в REPL в обоих режимах.

```sh
npm run dev
```

```text
/rag on
Что можно хранить в global?
/rag off
Что можно хранить в global?
/exit
```

`/rag on` печатает блок `── Режим ──` (`Ответы с RAG: стратегия structure, top-5.`), вопрос отвечает с блоком
`── Ответ агента · RAG ──` и фрагментами. После `/rag off` тот же вопрос даёт `── Ответ агента ──` без фрагментов.
В CLI (`npm run dev -- rag on`) режим действует только на этот запуск.

3. Контрольные вопросы в обоих режимах.

```sh
npm run dev -- rag eval
```

Ход операции идёт в stderr (`q01: без RAG`, `q01: с RAG`, …), итог — в stdout:

```text
── Контрольные вопросы ──

Вопросов: 10
Ожидаемые источники в top-5: 13 из 16
Время ответов: без RAG 30.6 с, с RAG 20.7 с

Сохранено: …/.local/rag/rag-eval.md
```

В `rag-eval.md` — сводка, для каждого вопроса найденные фрагменты, ожидаемые источники и ответы обоих режимов.
Числа — измерения одного прогона (Apple M4 Pro); найденные источники должны совпасть, время и ответы модели будут другими.

4. Другая стратегия чанкинга и другой top-K:

```sh
npm run dev -- --rag-chunk-strategy=fixed --rag-top-k=3 rag ask "Что можно хранить в global?"
```

## Ошибки

Без индекса — «Индекс не найден. Сначала выполните rag index.». Без ключа — «Задайте LAB_LLM_API_KEY в окружении процесса.»
(проверяется раньше, чем обращение к Ollama). Без Ollama — «Ollama недоступна по … Запустите ollama serve.». Индекс от другой
модели — «Индекс построен моделью …, а для запроса выбрана …. Пересоберите индекс: rag index.». Нет файла вопросов —
«Файл контрольных вопросов не найден. Проверьте rag.questionsFile.».

## Ограничения

Поиск — линейный перебор без порога релевантности: модель получает top-K и когда в документации ответа нет. Истории между
репликами нет, цитат и ссылок на фрагменты в ответе нет. `rag eval` — один прогон, DeepSeek недетерминирован. Попадание
источников считается по файлу, а не по разделу.
