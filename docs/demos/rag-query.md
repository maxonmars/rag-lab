# Первый RAG-запрос: ответ без RAG и с RAG

Цель: показать, как вопрос превращается в запрос к DeepSeek с найденными фрагментами документации, и чем ответ с RAG
отличается от ответа без него. Решение — [ADR 0003](../adr/0003-first-rag-query.md), результаты первого сравнения —
[experiments/feod-rag](../../experiments/feod-rag/README.md). Порог, rewrite и четыре режима поиска —
[демо режимов](retrieval-modes.md); ниже режим поиска — `baseline`, как в ADR 0003.

## Требования

- индекс из [демо индексации](indexing.md): `npm run corpus:feod`, затем `npm run dev -- rag index`;
- запущенная Ollama (`ollama serve`) и та же модель, что при построении индекса (`bge-m3`): при другом digest поиск отказывается работать;
- `LAB_LLM_API_KEY` в корневом `.env` или окружении процесса; значение нигде не печатается.

## Сценарий

1. Ответ с RAG одной командой. Под ответом печатаются найденные фрагменты: ранг, файл, первый раздел, сходство.

```sh
npm run dev -- --rag-retrieval-mode=baseline rag ask "Что можно хранить в global?"
```

Ожидается блок `── Ответ агента · RAG ──`: текст ответа (с источниками и цитатами — [демо цитат](citations.md)), пустая строка и `Фрагменты:` со строками вида
`1. structure/global.md › Global › Правило · 0.71`. Суффикс `(+N)` означает, что чанк касается ещё N разделов.
Число строк равно `rag.topK` (5); текст и сходство зависят от прогона. Без флага режим — `rewrite-filter`, строк может быть меньше.

2. Тот же вопрос в REPL в обоих режимах.

```sh
npm run dev
```

```text
/rag on
Что можно хранить в global?
/rag off
Что можно хранить в global?
/exit
```

`/rag on` печатает блок `── Режим ──` (`Ответы с RAG: стратегия structure, режим rewrite-filter, кандидатов 10, итоговый top-5, порог 0.55.`), вопрос отвечает с блоком
`── Ответ агента · RAG ──` и фрагментами. После `/rag off` тот же вопрос даёт `── Ответ агента ──` без фрагментов.
В CLI (`npm run dev -- rag on`) режим действует только на этот запуск.

3. Контрольные вопросы. Первый эксперимент ADR 0003 сравнивал ответы без RAG и с RAG; текущая команда `rag eval`
   сравнивает четыре режима поиска — см. [демо режимов](retrieval-modes.md), шаг 5. Отчёт первого сравнения сохранён в
   [experiments/feod-rag/rag-eval.md](../../experiments/feod-rag/rag-eval.md).

4. Другая стратегия чанкинга и другой top-K:

```sh
npm run dev -- --rag-chunk-strategy=fixed --rag-top-k=3 --rag-retrieval-mode=baseline rag ask "Что можно хранить в global?"
```

## Ошибки

Без индекса — «Индекс не найден. Сначала выполните rag index.». Без ключа — «Задайте LAB_LLM_API_KEY в окружении процесса.»
(проверяется раньше, чем обращение к Ollama). Без Ollama — «Ollama недоступна по … Запустите ollama serve.». Индекс от другой
модели — «Индекс построен моделью …, а для запроса выбрана …. Пересоберите индекс: rag index.». Нет файла вопросов —
«Файл контрольных вопросов не найден. Проверьте rag.questionsFile.».

## Ограничения

В режиме `baseline` модель получает top-K и когда в документации ответа нет; порог и rewrite — в [демо режимов](retrieval-modes.md).
Истории между репликами нет; источники и цитаты в ответе — в [демо цитат](citations.md). Попадание источников считается по файлу, а не по
разделу. DeepSeek недетерминирован.
