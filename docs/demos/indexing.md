# Индексация документов FEOD

Цель: показать, как корпус превращается в локальный индекс — чанки двух стратегий, эмбеддинги, метаданные — и чем
стратегии различаются. Решение — [ADR 0002](../adr/0002-document-indexing.md), результаты прогона —
[experiments/feod-chunking](../../experiments/feod-chunking/README.md).

## Требования

- `nvm use`, `npm ci`;
- запущенная Ollama (`ollama serve`) и модель: `ollama pull bge-m3` (около 1,2 ГБ);
- сеть только для `npm run corpus:feod` (клон репозитория) и скачивания модели; `rag index` и `rag compare` работают локально;
- ключ DeepSeek не нужен.

## Сценарий

1. Подготовить корпус: 32 документа на закреплённом коммите, frontmatter с `source` и `title`.

```sh
npm run corpus:feod
```

Ожидается `Корпус FEOD: 32 документов, 173774 символов, .local/rag/corpus`. Рядом лежат `CORPUS.md` (коммит, исключённые
разделы, размеры) и `LICENSE` (MIT).

2. Построить индекс обеими стратегиями (около 15 секунд на Apple M4 Pro).

```sh
npm run dev -- rag index
```

Ход операции идёт в stderr, итог — в stdout:

```text
fixed: разбиение, чанков 120
fixed: эмбеддинги, чанков 120
structure: разбиение, чанков 205
structure: эмбеддинги, чанков 205

── Индекс ──

Документов: 32, символов: 173 774
Модель: bge-m3:latest, digest 790764642607, размерность 1024
fixed: 120 чанков, токенов 53 824, эмбеддинги 7.9 с
structure: 205 чанков, токенов 49 804, эмбеддинги 7.4 с

Сохранено: …/.local/rag/index.json
```

Токены и время — значения одного прогона; у вас они будут немного другими, число чанков и токенов — теми же.

3. Показать метаданные чанка.

```sh
jq '.strategies.structure.chunks[3] | {chunk_id, source, title, file, sections, start, end}' .local/rag/index.json
jq '[.model.name, .model.dimension, (.strategies.fixed.chunks | length), (.strategies.structure.chunks | length)]' .local/rag/index.json
```

Каждый чанк несёт `chunk_id`, `source` (ссылка на файл закреплённого коммита), `title`, `file`, `sections` (пути
заголовков), `start`–`end` и вектор из 1024 чисел. Текст чанка равен срезу `documents[].text` по диапазону.

4. Сравнить стратегии и открыть отчёт.

```sh
npm run dev -- rag compare
```

```text
fixed: 120 чанков, размер 232–1 800, разорванных блоков 25
structure: 205 чанков, размер 222–1 800, разорванных блоков 6
```

В `.local/rag/comparison.md` — таблицы измерений и раздел «Ручное сравнение»: для трёх участков корпуса показан исходный
текст и границы чанков обеих стратегий. В кадр стоит взять таблицу разрешённых импортов: `fixed` режет её посреди
строки, `structure` оставляет целой. Правило с исключением разорвали обе стратегии — это тоже наблюдение.

5. Попробовать другие параметры (перекрытие и минимальный чанк должны укладываться в размер):

```sh
npm run dev -- --rag-chunk-size-chars=1200 --rag-min-chunk-chars=300 --rag-output-dir=.local/rag-1200 rag index
```

## Ошибки

Без Ollama `rag index` завершится сообщением «Ollama недоступна по http://localhost:11434. Запустите ollama serve.» и
кодом 1; старый `index.json` при этом не меняется. Без модели — «Модель bge-m3 не найдена в Ollama. Выполните: ollama pull bge-m3».
`rag compare` без индекса подсказывает выполнить `rag index`.

## Ограничения

Качество поиска не измеряется: поиска в индексе пока нет. Время — одиночный прогон. Модель эмбеддингов выбрана по
опубликованным результатам на русских задачах MTEB, а не по замеру на этом корпусе.
