# RAG-чат: история и память задачи

Цель: показать, что в режиме `/rag on` каждая реплика ищет контекст в индексе и получает ответ с источниками, память задачи
пополняется тем, что сказал пользователь, а ответ опирается на неё, даже когда ход выпал из окна истории. Решение —
[ADR 0006](../adr/0006-rag-chat-memory.md), результаты на двух длинных сценариях — [experiments/feod-chat](../../experiments/feod-chat/README.md).

## Требования

- индекс из [демо индексации](indexing.md): `npm run corpus:feod`, затем `npm run dev -- rag index`;
- запущенная Ollama с той же моделью, что при построении индекса (`bge-m3`, [docs/ollama.md](../ollama.md));
- `LAB_LLM_API_KEY` в корневом `.env`.

## Сценарий

1. Запустить REPL с окном истории в один ход: модель видит только предыдущую пару «вопрос — ответ», всё более раннее доходит до
   неё только через память задачи.

```sh
npm run dev -- --rag-history-turns 1
```

```text
/rag on
Мы переводим наш frontend-проект с FSD на FEOD. Какие верхние уровни есть в FEOD?
Уточню: проект на TypeScript, около 40 страниц, слой shared сейчас общий для всего.
Важное ограничение: deep imports в новом коде запрещаем сразу, без исключений.
Куда при переезде деть наш слой shared?
Как на code review проверять, что наше ограничение соблюдается?
```

`/rag on` печатает блок `── Режим ──` со строкой `Ответы учитывают историю (последние 1 ходов) и память задачи`. Каждая реплика
даёт блок `── Ответ агента · RAG-чат · <провайдер · модель> ──`: ответ, `Источники:` и `Цитаты:` с проверкой дословности, `Фрагменты:`, строку
`Цель:` и строку `Память:` — `добавлено` со списком новых пунктов или `без изменений`. Ожидаемая память по ходам:

| Ход | Строка `Память:` | Что видно в ответе |
|---|---|---|
| 1 | добавлено: цель «Перевести frontend-проект с FSD на FEOD» | уровни `app`, `pages`, `modules`, `common`, `global` |
| 2 | добавлено: уточнения про TypeScript, 40 страниц и общий `shared` | ответ ссылается на уточнение («С учётом вашего уточнения…») |
| 3 | добавлено: ограничение про deep imports | ответ называет ограничение пользователя |
| 4 | без изменений | «наш слой shared» раскрыт: разбор `shared` на `common`, `global` и модули |
| 5 | без изменений | «наше ограничение» раскрыто как запрет deep imports, хотя ход 3 уже вне окна истории |

Вопросы и просьбы в память не попадают: в ходах 4 и 5 пользователь ничего не сообщает о задаче, поэтому память не меняется.
Формулировки памяти и ответов зависят от модели; пункт, который модель переформулировала, тоже показывается как добавленный.

2. Тот же вопрос без истории и памяти — `/rag ask`; затем память целиком и сброс.

```text
/rag ask Как на code review проверять, что наше ограничение соблюдается?
/rag state
/rag reset
/rag state
/exit
```

Блок `── Ответ агента · RAG · <провайдер · модель> ──` (без `Цель:` и `Память:`) не знает, какое ограничение имеется в виду: в прогонах 2026-10-04 это
был «Не знаю» с вопросом «О каком именно ограничении идёт речь?» или общий ответ про checklist без deep imports. `/rag ask` диалог не
меняет: `/rag state` печатает `── Память задачи ──` с `Ходов: 5` и разделами `Цель`, `Уточнения` (TypeScript, 40 страниц,
`shared`), `Ограничения и термины` (deep imports). `/rag reset` отвечает «Диалог и память задачи сброшены.», повторный
`/rag state` — «Память задачи пуста.».

3. Два длинных сценария эксперимента (13 и 12 реплик, около двух минут) и отчёт `rag-dialog.md`. Ход печатается в stderr
   (`s1: ход 1`, …), итог — в stdout.

```sh
npm run dev -- rag dialog
cp .local/rag/rag-dialog.md experiments/feod-chat/rag-dialog.md
```

Ожидается блок `── Контрольные вопросы ──`: число сценариев, реплик, режим, окно истории; на сценарий — ходов, ответов с источниками,
цель сохранена, ключи памяти, «не знаю» и длительность; путь к `.local/rag/rag-dialog.md`. На каждую реплику сценариев в корпусе есть
ответ, поэтому ожидается ответ с источником на каждом ходу; в итоговом прогоне — 12 из 13 и 12 из 12, цель и ключи памяти
сохранены на всех ходах ([README эксперимента](../../experiments/feod-chat/README.md)). В отчёте — сводка, таблица ходов со строкой
поиска, фрагменты с `chunk_id`, ответ и память после каждого хода; оценок смысла в нём нет.

## Ошибки

Нет индекса, ключа, Ollama — как в [демо RAG-запроса](rag-query.md). Ошибка модели посреди хода не меняет диалог: REPL печатает
ошибку, следующая реплика видит прежнюю историю. Первая ошибка во время `rag dialog` прерывает прогон, прежний отчёт остаётся.
Файл сценариев — `rag.dialogFile`; формат — [scenarios.md](../../experiments/feod-chat/scenarios.md).

## Ограничения

Диалог хранится только в памяти сессии REPL и теряется при выходе; в CLI режим RAG и диалог действуют один запуск. Память задачи
пишет модель и видит только реплики пользователя: согласие с предложением ассистента («да, так и сделаем») она не раскроет —
условие нужно назвать самому. Rewrite иногда вопреки промпту дописывает к запросу цель диалога, и поиск уходит к общим страницам —
тогда ответ «не знаю» при ответе в корпусе. В режимах `baseline` и `filter` follow-up ищется по исходной формулировке, без памяти и
истории. DeepSeek недетерминирован, ожидания выше — по двум ручным прогонам.
