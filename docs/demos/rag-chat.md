# RAG-чат: история и память задачи

Цель: показать, что в режиме `/rag on` реплики идут с историей диалога и памятью задачи, каждый ответ содержит источники,
а `/rag state` и `/rag reset` показывают и сбрасывают память. Решение — [ADR 0006](../adr/0006-rag-chat-memory.md), результаты на
двух сценариях — [experiments/feod-chat](../../experiments/feod-chat/README.md).

## Требования

- индекс из [демо индексации](indexing.md): `npm run corpus:feod`, затем `npm run dev -- rag index`;
- запущенная Ollama с той же моделью, что при построении индекса (`bge-m3`, [docs/ollama.md](../ollama.md));
- `LAB_LLM_API_KEY` в корневом `.env`.

## Сценарий

1. Запустить REPL и ввести реплики по порядку. Цель названа в первой реплике, вторая отсылается к первой местоимением.

```sh
npm run dev
```

```text
/rag on
Моя цель — перевести проект с FSD на FEOD. Какие верхние уровни есть в FEOD?
А что из них может импортировать код страниц?
/rag state
/rag reset
/rag state
/exit
```

`/rag on` печатает блок `── Режим ──`, в том числе строку про историю (последние `rag.historyTurns` ходов) и память задачи. Каждая из
двух реплик даёт блок `── Ответ агента · RAG-чат ──`: ответ с `Источники:` и `Цитаты:`, список `Фрагменты:` и строку
`Цель: Перевести проект с FSD на FEOD.` (обычно уже после первой реплики). Во втором ходу «из них» раскрывается по истории и
памяти: rewrite получает память задачи и последние реплики, а модель — первую пару «вопрос — ответ» отдельными сообщениями.
`/rag state` печатает блок `── Память задачи ──` с числом ходов (`Ходов: 2`) и разделами `Цель`, `Уточнения`,
`Ограничения и термины`. `/rag reset` отвечает «Диалог и память задачи сброшены.», повторный `/rag state` — «Память задачи пуста.».
Формулировка памяти и ответов зависит от модели и меняется от прогона к прогону.

2. Сравнить с одиночным вопросом: `/rag ask` отвечает по фрагментам без истории и памяти и диалог не меняет.

```text
/rag on
Моя цель — перевести проект с FSD на FEOD. Какие верхние уровни есть в FEOD?
/rag ask А что из них может импортировать код страниц?
/rag state
```

Блок `── Ответ агента · RAG ──` (без `Цель:`) отвечает на вопрос без контекста первой реплики, а `/rag state` показывает `Ходов: 1`.

3. Два длинных сценария эксперимента (25 реплик, около двух минут) и отчёт `rag-dialog.md`. Ход печатается в stderr
   (`s1: ход 1`, …), итог — в stdout.

```sh
npm run dev -- rag dialog
cp .local/rag/rag-dialog.md experiments/feod-chat/rag-dialog.md
```

Ожидается блок `── Контрольные вопросы ──`: число сценариев, реплик, режим, окно истории; на сценарий — ходов, ответов с источниками,
цель сохранена, ключи памяти, «не знаю» и длительность; путь к `.local/rag/rag-dialog.md`. В отчёте — сводка, таблица ходов,
фрагменты с `chunk_id`, ответ и память после каждого хода; оценок смысла в нём нет.

## Ошибки

Нет индекса, ключа, Ollama — как в [демо RAG-запроса](rag-query.md). Ошибка модели посреди хода не меняет диалог: REPL печатает
ошибку, следующая реплика видит прежнюю историю. Первая ошибка во время `rag dialog` прерывает прогон, прежний отчёт остаётся.
Файл сценариев — `rag.dialogFile`; формат — [scenarios.md](../../experiments/feod-chat/scenarios.md).

## Ограничения

Диалог хранится только в памяти сессии REPL и теряется при выходе; в CLI режим RAG и диалог действуют один запуск. Память задачи
пишет модель: она может записать вопрос или утверждение ассистента. Окно истории ограничено `rag.historyTurns`. В режимах `baseline` и
`filter` follow-up ищется по исходной формулировке, без памяти и истории. DeepSeek недетерминирован, прогон один.
