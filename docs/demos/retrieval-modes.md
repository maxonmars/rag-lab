# Порог релевантности, rewrite и сравнение четырёх режимов

Цель: показать, как порог сходства и переписывание запроса меняют контекст, и подобрать порог по контрольным вопросам.
Решение — [ADR 0004](../adr/0004-relevance-filter-and-query-rewrite.md), вопросы и результаты —
[experiments/feod-retrieval](../../experiments/feod-retrieval/README.md).

## Требования

- индекс из [демо индексации](indexing.md): `npm run corpus:feod`, затем `npm run dev -- rag index`;
- запущенная Ollama с той же моделью, что при построении индекса (`bge-m3`, [docs/ollama.md](../ollama.md));
- `LAB_LLM_API_KEY` в корневом `.env` для `rag ask` и `rag eval`; `rag calibrate` ключа не требует.

## Сценарий

1. Калибровка порога на исходных вопросах q01–q10. Один поиск на вопрос, пороги 0.50, 0.55, 0.60, 0.65 на общих
   кандидатах; ход печатается в stderr, итог — в stdout.

```sh
npm run dev -- rag calibrate --rag-questions-file experiments/feod-rag/questions.md
```

Ожидается блок `── Калибровка порога ──` со строкой на каждый порог («сохранено пар», «потеряно», «отрицательных с пустым
контекстом»), строкой `Рекомендуемый порог: …` и путём к `.local/rag/rag-calibration.md`. Настройки команда не меняет.

2. Ответ в режиме по умолчанию (`rewrite-filter`): DeepSeek переписывает вопрос, поиск возвращает 10 кандидатов, отбор
   оставляет чанки со сходством не ниже 0.55, но не больше 5.

```sh
npm run dev -- rag ask "Что можно хранить в global?"
```

Под ответом печатаются только чанки, которые получила модель. Если отбор ничего не оставил, вместо списка выводится
`Фрагменты: контекст пуст`: модель не вызывалась, ответ — «не знаю» с просьбой уточнить вопрос; это не утверждение, что в корпусе ответа нет.

3. Тот же вопрос в других режимах — сравните строки «Фрагменты»:

```sh
npm run dev -- --rag-retrieval-mode=baseline rag ask "Что можно хранить в global?"
npm run dev -- --rag-retrieval-mode=filter rag ask "Какой state-менеджер рекомендует FEOD?"
npm run dev -- --rag-similarity-threshold=0.65 rag ask "Что можно хранить в global?"
```

`baseline` всегда возвращает `rag.topK` чанков; `filter` может вернуть меньше или ни одного: на вопросе про state-менеджер строка
«Фрагменты» будет `контекст пуст`. Порог не гарантирует пустой контекст для всех вопросов без ответа (вопрос про версию React проходит порог): тогда отказ
зависит от модели, подробнее — [демо цитат](citations.md). Пустой контекст сам даёт «не знаю» без вызова модели. `--rag-candidate-top-k` больше
`--rag-top-k` сам по себе выдачу фильтра не меняет — он только позволяет порогу увидеть кандидатов дальше `topK`.

4. REPL: `/rag on` показывает режим, лимиты и порог; обычные строки идут по настроенному конвейеру.

```sh
npm run dev
```

```text
/rag on
Что можно хранить в global?
/rag off
/exit
```

5. Сравнение всех четырёх режимов на 15 вопросах. Команда игнорирует `rag.retrievalMode` и на вопрос делает два поиска,
   один rewrite и до четырёх генераций (в режимах с фильтром при пустом контексте генерации нет): до 75 вызовов модели на 15 вопросах.

```sh
npm run dev -- rag eval
cp .local/rag/rag-eval.md experiments/feod-retrieval/rag-eval.md
```

Ход печатается в stderr (`q01: поиск исходным вопросом`, `q01: baseline`, `q01: filter`, `q01: переписывание запроса`, …),
итог — в stdout: по строке на режим с hit@5, MRR, покрытием источников и долей отрицательных вопросов с непустым
контекстом, плюс длительность прогона. В `rag-eval.md` — сводка, исходный и переписанный запрос, кандидаты со scores и
причиной исключения («передан», «ниже порога», «вне top-K»), ответы всех режимов и время этапов.

## Ошибки

Несогласованные лимиты (`rag.topK` больше `rag.candidateTopK`) отклоняются до обращения к Ollama и модели: «rag.topK не
должен превышать rag.candidateTopK.». Ответ rewrite из нескольких строк или в Markdown-заборе — «Модель вернула
некорректный поисковый запрос: …»; поиск и ответ не выполняются, исходный вопрос не подставляется. Остальные ошибки —
как в [демо RAG-запроса](rag-query.md).

## Ограничения

Числа `rag eval` — один прогон одной модели на одном корпусе; DeepSeek недетерминирован. Метрики считаются по файлам
итоговых чанков, а не по релевантности чанков и не по качеству ответа; уменьшение контекста не доказывает улучшение
ответа. Время режима — сумма его этапов, включая общие с парным режимом. Токены и стоимость не считаются.
