# RAG-чат с памятью задачи на документации FEOD

Пятое задание недели RAG: REPL-чат хранит историю диалога, на каждую реплику ищет контекст в индексе, всегда выводит источники и
ведёт память задачи (цель, уточнения, ограничения и термины пользователя). Проверка — два сценария по 12–13 реплик
([scenarios.md](scenarios.md)): в первом пользователь переводит проект с FSD на FEOD, во втором проектирует модуль корзины.
На каждую реплику в корпусе есть ответ; часть реплик понятна только через память («наше ограничение», «наш термин»), итоговая
реплика проверяет, что цель и договорённости не потеряны. Разделы «Условия прогона» и «Измерения» — вывод `rag dialog`
([rag-dialog.md](rag-dialog.md)) и вычисления по нему, помеченные как вычисленные; «Ручная оценка» и «Выводы» — оценки, они
опираются на измерения и отделены от них. Решение — [ADR 0006](../../docs/adr/0006-rag-chat-memory.md), демо —
[docs/demos/rag-chat.md](../../docs/demos/rag-chat.md).

**Ручная оценка — черновик, требует подтверждения автором.** Её поставил агент-кодер по [rag-dialog.md](rag-dialog.md): память после
каждого из 25 ходов прочитана целиком, ответы ходов s1/4, s1/8, s1/9, s1/12, s1/13 и s2/8, s2/9, s2/11, s2/12 — целиком, остальные — по
началу текста и цитатам. Спорные случаи стоит перечитать.

Системная инструкция ответа — `app/system.md` плюс `prompts/answer.md` и `prompts/chat.md`; память обновляет `prompts/task-state.md`
(на входе память и новое сообщение пользователя, без ответов ассистента), rewrite использует `prompts/rewrite-chat.md`. Ответы
ассистента в истории идут в полном формате ответа. Повторного вызова модели при нарушении формата ответа или памяти нет.

**Промпты и сценарии подбирались на этих же сценариях.** На прежних сценариях (с вопросами вне корпуса и вопросом «напомни цель»)
и прежнем коде полные прогоны дали 17, 16, 20, 18 и 19 ответов с источником из 25. После замены этих вопросов на вопросы с ответом
в корпусе: 20 из 25 с историей без источников и цитат, затем 23 из 25 и 24 из 25 (итоговый) на текущем коде; между двумя последними
переформулирована реплика s2/10, ход которой не прошёл порог. Итоговый прогон — не независимая проверка на новых данных.

## Воспроизведение

Нужны запущенная Ollama с `bge-m3` ([docs/ollama.md](../../docs/ollama.md)), индекс и `LAB_LLM_API_KEY` в корневом `.env`.

```sh
npm run corpus:feod
ollama pull bge-m3
npm run dev -- rag index
npm run dev -- rag dialog
cp .local/rag/rag-dialog.md experiments/feod-chat/rag-dialog.md
```

Переписанные запросы, память и ответы DeepSeek при повторе будут отличаться, а вместе с ними набор переданных фрагментов и
число ответов с источниками. Файл сценариев по умолчанию — `experiments/feod-chat/scenarios.md` (`rag.dialogFile`).

Фрагменты документации FEOD в отчёте — Copyright (c) 2026 FEOD Architecture, лицензия MIT
([LICENSE](https://github.com/feod-architecture/feod-docs/blob/f00eaf533cfee37f67e118c96291d535b0895a6f/LICENSE)).

## Ручная оценка

Шкала для ответов и отказов — как в [feod-citations](../feod-citations/README.md): «подтверждается», «частично», «не подтверждается»
для ответов; «отказ верен» или «ложный отказ» для отказов. Для памяти: «корректна» — в памяти только сказанное пользователем;
«с замечанием» — есть пункт, которого пользователь не говорил. Наличие ответа в корпусе проверялось поиском по `.local/rag/corpus`.

| Показатель | Оценка | Комментарий |
|---|---|---|
| Цель | не потеряна | На всех 25 ходах цель в памяти — «Перевести frontend-проект с FSD на FEOD» (s1) и «Спроектировать новый модуль корзины (cart) для интернет-магазина по FEOD» (s2), без изменений с первого хода |
| Память после хода | корректна на 25 ходах из 25 | Пункты появляются только в ходах, где пользователь что-то сообщил: s1/1, s1/2, s1/6, s1/7 («В проекте уже существуют legacy deep imports» — из вопроса пользователя), s2/1, s2/3, s2/5, s2/6. Утверждений ассистента и пересказов вопросов нет |
| Использование памяти | видно в ответах | «Наши слои» (s1/9), «наше ограничение» (s1/12), «наш термин» (s2/11) и «наши договорённости» (s2/12) раскрыты в строке поиска и в ответе. Итоговые s1/13 (план из 5 шагов) и s2/12 (структура `cart`) называют запрет deep imports, термин public API = `index.ts` и ограничение про `global` |
| Ответы с источниками | подтверждаются на проверенных ходах, кроме одного «частично» | **s2/12 — частично:** «общий код корзины и каталога не кладём в `global`, поэтому он не должен попадать и в `cart`» — вывод не следует ни из ограничения пользователя, ни из фрагмента [4]. Остальные проверенные ответы опираются на цитаты и фрагменты |
| Шаблонность | заметна | В s1 почти каждый ответ начинается с «С учётом цели перевести проект с FSD на FEOD», даже когда цель на ответ не влияет (s1/3, s1/5) |
| Цитаты | дословны, по содержанию уместны на проверенных ходах | Пустых цитат вроде «Плохо:» в этом прогоне нет |

Отказы:

|---|---|---|---|---|
| s1/8 | Где хранить API-клиент? | не знаю (модель) | ложный отказ | Ответ есть в `get-started/faq.md` («Где хранить API-клиент?»), одиночный `rag ask` его находит (сходство 0.71). ## Выводы

Это один итоговый прогон одной модели на одном корпусе и оценки одного рецензента; ниже — только то, что следует из чисел и оценок
выше.

1. **Цель и договорённости удержаны на всех ходах.** 25 из 25 по метрике цели и 37 из 37 проверок ключей памяти; ручное чтение
   памяти после каждого хода подтверждает, что в ней только сказанное пользователем. Метрика проверяет подстроки, а не смысл.
2. **Ответ с источником — на 24 ходах из 25.** Единственное исключение — ложный отказ s1/8 из-за rewrite. Цитаты дословны в 71 из 71
   случаев, нарушений формата нет. В прежних прогонах ответы без раздела «Ответ» или без «Источников» появлялись, когда реплики
   ассистента в истории шли в другом формате: модель копирует историю охотнее, чем инструкцию.
3. **Память видна в ответах, а не только в `/rag state`.** Отсылки «наше ограничение», «наш термин» раскрываются через память, и
   20 ответов из 25 явно называют пункт памяти. Цена — шаблонная вводная фраза про цель в начале многих ответов s1.
4. **Rewrite с памятью остаётся слабым местом.** Промпт запрещает дописывать цель, если вопрос на неё не ссылается, но в s1/8 модель
   это сделала, и поиск ушёл от FAQ. В прогонах на прежнем промпте так же терялись ответы про API-клиент в s1 и s2.
5. **Стоимость чата — три вызова на ход.** 75 вызовов на 25 реплик против одного вызова на реплику без RAG и до двух с `rag ask`;
   ход занимает 3.5–5.4 с. Разброс между прогонами (23 и 24 из 25 на текущем коде) не позволяет считать разницу в один ход эффектом.
6. **Не измерено:** влияние окна `rag.historyTurns` (обрезка начинается с 8-го хода, сравнения с другим окном нет; в демо окно 1
   показано вручную), сравнение с чатом без памяти задачи на этих сценариях, отказы на вопросах вне корпуса внутри диалога, токены и
   стоимость, другие режимы поиска, независимые от подбора промптов сценарии.
