# RAG-чат с памятью задачи на документации FEOD

Пятое задание недели RAG: REPL-чат хранит историю диалога, на каждую реплику ищет контекст в индексе, всегда выводит источники и
ведёт память задачи (цель, уточнения, ограничения и термины пользователя). Проверка — два сценария по 12–13 реплик
([scenarios.md](scenarios.md)): в первом пользователь переводит проект с FSD на FEOD, во втором проектирует модуль корзины.
В каждом есть отвлечённый вопрос без ответа в корпусе и итоговая реплика, которая проверяет, что цель и договорённости не потеряны.
Разделы «Условия прогона» и «Измерения» — вывод `rag dialog` ([rag-dialog.md](rag-dialog.md)) и вычисления по нему, помеченные как
вычисленные; «Ручная оценка» и «Выводы» — оценки, они опираются на измерения и отделены от них. Решение —
[ADR 0006](../../docs/adr/0006-rag-chat-memory.md), демо — [docs/demos/rag-chat.md](../../docs/demos/rag-chat.md).

**Ручная оценка — черновик, требует подтверждения автором.** Её поставил агент-кодер по [rag-dialog.md](rag-dialog.md): память после
каждого из 25 ходов прочитана целиком, ответы ходов s1/7, s1/12 и s2/8, s2/12 — целиком, остальные — по началу текста и цитатам.
Спорные случаи стоит перечитать.

Системная инструкция ответа — `app/system.md` плюс `prompts/answer.md` и `prompts/chat.md`; память обновляет `prompts/task-state.md`,
rewrite использует `prompts/rewrite-chat.md`. Повторного вызова модели при нарушении формата ответа или памяти нет.

**Промпты подбирались на этих же сценариях.** До итогового прогона один запуск оборвался на 2-й реплике (ответ упёрся в
`llm.maxOutputTokens`), три полных прогона и несколько сокращённых (до 9 реплик на сценарий) шли при правке `chat.md` и
`task-state.md`. В четырёх полных прогонах до и включая итоговый ответов с источником было 17, 16, 20 и 18 из 25: это оценка шума
между прогонами, а итоговый прогон нельзя считать независимой проверкой на новых данных.

## Воспроизведение

Нужны запущенная Ollama с `bge-m3` ([docs/ollama.md](../../docs/ollama.md)), индекс и `LAB_LLM_API_KEY` в корневом `.env`.

```sh
npm run corpus:feod
ollama pull bge-m3
npm run dev -- rag index
npm run dev -- rag dialog
cp .local/rag/rag-dialog.md experiments/feod-chat/rag-dialog.md
```

Переписанные запросы, память и ответы DeepSeek при повторе будут отличаться, а вместе с ними набор переданных фрагментов и
число ответов с источниками. Файл сценариев по умолчанию — `experiments/feod-chat/scenarios.md` (`rag.dialogFile`).

([LICENSE](https://github.com/feod-architecture/feod-docs/blob/f00eaf533cfee37f67e118c96291d535b0895a6f/LICENSE)).

## Ручная оценка

Шкала для ответов и отказов — как в [feod-citations](../feod-citations/README.md): «подтверждается», «частично», «не подтверждается»
для ответов; «отказ верен» или «ложный отказ» для отказов. Для памяти: «корректна» — в памяти только сказанное пользователем;
«с замечанием» — есть пункт, которого пользователь не говорил или который он не подтверждал. Наличие ответа в корпусе проверялось
поиском по `.local/rag/corpus` и по ожиданиям [feod-retrieval](../feod-retrieval/questions.md).

| Показатель | Оценка | Комментарий |
|---|---|---|
| Цель | не потеряна | На всех 25 ходах цель в памяти — «Перевести frontend-проект с FSD на FEOD» (s1) и «Пользователь проектирует новый модуль корзины (cart) для интернет-магазина по FEOD» (s2). Отвлечённые вопросы (s1/9, s2/10) её не изменили, следующий ответ вернулся к теме |
| Термины и ограничения | запомнены | `deep imports` (s1/6), термин `public API` (s2/3) и ограничение про `global` (s2/6) записаны в ход, где их назвал пользователь, и остались до конца. Итоговые ответы s1/13 (план из 5 шагов называет запрет deep imports в новом коде) и s2/12 (структура `cart` с корневым `index.ts`, без `global`) их учитывают |
| Память после хода | корректна на 23 ходах из 25, с замечанием на 2 | **s1/5:** в «Уточнения» попали три утверждения ассистента из ответа s1/4 (куда деть `shared`, что `shared` — не автоматический `common`, что UI-примитивы не стоит делать модулями), хотя пользователь их не подтверждал. **s2/8:** «Есть общие типы цены и форматирование цены, которые нужно куда-то положить» — пересказ вопроса пользователя. Метрика ключей этого не видит |
| Последствие утечки | заметно | В ответе s1/12 («какая у нас цель и какие ограничения») к запрету deep imports добавлены как «договорённости» разбор `shared` и UI-примитивы: пользователь их не принимал. Цитаты этого ответа найдены дословно, но не подтверждают ни цель, ни ограничения, а одна из них — вопросительная строка «Нужно ли менять внутренности без поломки потребителей?» |
| Ответы с источниками | подтверждаются на проверенных ходах | s1/12 и s2/12 (итоги) сверены целиком: каждое утверждение, кроме пересказа памяти, опирается на цитату или фрагмент; в s2/12 ответ сам отмечает, что фрагмент по `common` обрывается. Остальные ответы прочитаны по началу и цитатам: противоречий фрагментам не замечено |
| Цитаты | часть пустая по содержанию | Дословность не равна подтверждению (см. вывод 2 [feod-citations](../feod-citations/README.md)): в s2/5 цитата — «Плохо:», в s2/7 — «В `global` нельзя хранить:» |
| Нарушения формата | 2 из 25 | s1/7, s2/7: ответ начинается без заголовка «Ответ», хотя разделы «Источники» и «Цитаты» есть. Текст ответов по содержанию верен |

## Выводы

Это один итоговый прогон одной модели на одном корпусе и оценки одного рецензента; ниже — только то, что следует из чисел и оценок
выше.

1. **Цель и ключевые договорённости удержаны на всех ходах.** 25 из 25 ходов по метрике цели и 37 из 37 проверок ключей памяти,
   что подтверждает и ручное чтение памяти после каждого хода. Метрика проверяет подстроки, а не смысл.
2. **Источники есть в 18 ответах из 25.** Ещё в двух ходах источники есть в тексте, но без раздела «Ответ» (нарушение формата,
   2 из 25; в одиночных вопросах [feod-citations](../feod-citations/README.md) их не было — но вопросы другие, связь с историей не
   проверена). Пять ходов — «не знаю», из них два верных отказа по пустому отбору. Цитаты найдены дословно в 49 из 51 случаев.
3. **Память записывает лишнее, и метрика этого не замечает.** Утверждения ассистента и пересказ вопроса попали в «Уточнения»
   (2 хода из 25), а на запрос «какие ограничения мы зафиксировали» ответ выдал их как договорённости. Промпт `task-state.md`
   запрещает это, но модель его не соблюдает полностью.
4. **Rewrite с памятью может увести поиск от вопроса.** Запросы s1/8 и s2/9 несут ограничения диалога, ответа про API-клиент среди
   фрагментов нет, хотя в корпусе он есть: два ложных отказа из пяти. Это цена общей памяти в запросе поиска; другие режимы поиска
   в чате не измерялись.
5. **Стоимость чата — три вызова на ход.** 73 вызова на 25 реплик против одного вызова на реплику без RAG и до двух с `rag ask`;
   ход занимает 2.2–5.5 с. Разброс между прогонами заметен (17, 16, 20, 18 ответов с источником из 25 в четырёх полных прогонах),
   поэтому разницу в один-два хода нельзя считать эффектом.
6. **Не измерено:** влияние окна `rag.historyTurns` (обрезка начинается с 8-го хода, но сравнения с другим окном нет), сравнение с чатом без памяти
   задачи, токены и стоимость, другие режимы поиска, независимые от подбора промптов сценарии.
