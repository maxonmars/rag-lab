# Сравнение стратегий чанкинга на документации FEOD

Первое задание недели RAG: одни и те же 32 документа режутся двумя стратегиями, для чанков считаются эмбеддинги,
затем стратегии сравниваются по форме чанков и по сохранности смысла. Раздел «Измерения» — вывод `rag compare`
без правок; «Выводы» — оценки автора, они опираются на эти измерения и отделены от них.

## Условия прогона

| Параметр | Значение |
|---|---|
| Дата | 2026-09-29, один локальный прогон после прогрева модели |
| Корпус | [feod-docs](https://github.com/feod-architecture/feod-docs) на коммите `f00eaf533cfee37f67e118c96291d535b0895a6f`, MIT, 32 русских документа из get-started, core-concepts, structure, guides, reference |
| Модель | `bge-m3:latest` в Ollama 0.34.4, digest `790764642607`, 1024 измерения, обрезка отключена |
| Параметры | размер 1800, перекрытие 200, минимальный чанк 500 (кодовые точки Unicode) |
| Машина | Apple M4 Pro, 48 ГБ, Node 24.12.0 |

Воспроизведение:

```sh
npm run corpus:feod
ollama pull bge-m3
npm run dev -- rag index
npm run dev -- rag compare
```

Полный отчёт с тремя разобранными участками — [comparison.md](comparison.md), копия `.local/rag/comparison.md`.

## Выводы

Это оценки по одному корпусу и одному прогону.

1. **`structure` реже разрывает смысловые блоки.** Он не поместил целиком 6 блоков из 1 201 (5 длинных списков «Шаги»
   и таблица глоссария — все длиннее лимита), а `fixed` — 25: 3 таблицы из 12 и 22 списка из 178. Абзацы и код
   `fixed` сохранил целыми: блок короче перекрытия (200) разорваться не может, а из 110 абзацев и блоков кода длиннее
   200 символов на границу окна не попал ни один — это совпадение положений на этом корпусе, а не свойство стратегии.
2. **Перекрытие `fixed` стоит дороже.** Повторённый текст — 17 600 символов (10,1% корпуса) против 2 800 (1,6%).
   Суммарно `structure` отправил модели на 4 020 токенов меньше (49 804 против 53 824), хотя чанков у него в 1,7 раза больше.
3. **Чанки `fixed` начинаются где придётся** — например, с середины слова «твенных подмодулей» — и почти всегда
   захватывают несколько разделов (108 из 120), поэтому один вектор смешивает темы. У `structure` многораздельных
   чанков 129 из 205, но это результат слияния коротких разделов (218 из 355 разделов H2/H3 короче 400 символов — разовый подсчёт при подготовке).
4. **Структура не гарантирует, что участок останется одним куском.** «Уровень app» уместился в одно окно `fixed`,
   а `structure` разделил его по подразделам; правило с исключением разорвали обе стратегии, потому что между ними
   больше лимита. Разница лишь в месте разреза: у `structure` он по заголовку, у `fixed` — внутри списка.
5. **Слабое место `structure` — длинные списки.** Блок длиннее лимита делится окнами так же, как в `fixed`;
   5 из 6 таких случаев — списки шагов в guides. Деление по пунктам списка — кандидат на улучшение, сегодня не сделано.
6. **Цена `structure` — больше векторов.** 205 против 120 при том же корпусе; влияние на скорость и качество поиска
   не измерялось.

Что не проверено: качество поиска (для него нужны контрольные вопросы и поиск — следующие задания), зависимость
результата от размера чанка и перекрытия, другие модели эмбеддингов, разброс времени между прогонами.
