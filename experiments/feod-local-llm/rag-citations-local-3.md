> Да, модуль может импортировать другой модуль, но только через его public API (без создания циклической или скрытой зависимости). Это означает, что импорт должен происходить из корня модуля (например, `@/modules/billing`), а не из его внутренних файлов, таких как модель или утилиты (например, `@/modules/billing/model/money`) [2]. ## q08. Чем FEOD отличается от FSD?

**Ожидание.** это отдельная методология, а не переименование FSD; основной термин — уровень, а не слой; нет обязательных слоёв entities, features, widgets; главный строительный блок — модуль с public API и контролируемыми зависимостями.

### Ответ

> FEOD и FSD решают одну задачу — делают frontend-архитектуру понятной и устойчивой, — но FEOD описывает её через уровни `app`, `pages`, `modules`, `common`, `global`, где главным строительным блоком является модуль [1]. Практическая разница состоит в том, что в FEOD основным термином служит уровень, а не слой, нет обязательного набора FSD-слоёв вроде `entities`, `features`, `widgets`, а акцент делается на модуле, его `public API` и границе зависимостей [1]. FEOD проще применять в проектах, где не нужна глубокая таксономия доменных типов, но требуются строгие правила импортов и масштабируемая структура [1]. Для команд из FSD рекомендуется сначала сопоставить текущие `entities`, `features` и `widgets` с будущими `modules`, а затем проверить public API каждого модуля [2].
