# Локальная и облачная модель в RAG: качество, скорость, стабильность

Задание седьмого дня недели RAG: подключить к RAG-конвейеру локальную LLM и сравнить её с облачной по качеству, скорости и
стабильности. Конвейер тот же, что в [feod-citations](../feod-citations/README.md): rewrite запроса, поиск, отбор по порогу,
ответ с источниками и цитатами. Меняется только `llm.provider` ([ADR 0007](../../docs/adr/0007-local-llm-provider.md)): `deepseek`
(`deepseek-flash`) или `local` (`qwen3.8:27b-mlx` в Ollama). Эмбеддинги в обоих случаях считает `bge-m3` в локальной Ollama.
10 вопросов — [../feod-citations/questions.md](../feod-citations/questions.md) без изменений: 7 положительных и 3 отрицательных
(q10, q14, q15). По 3 прогона `rag citations` на провайдера; демо — [docs/demos/local-llm.md](../../docs/demos/local-llm.md).

Разделы «Условия прогона» и «Измерения» — вывод `rag citations` (шесть отчётов рядом, формат описан в
[feod-citations](../feod-citations/README.md)); «Вычислено по отчётам» — арифметика над ними; «Ручная оценка» и «Выводы» —
оценки, они опираются на измерения и отделены от них.

**Ручная оценка — черновик агента, требует подтверждения автором.**

## Воспроизведение

Нужны запущенная Ollama с `bge-m3` и `qwen3.8:27b-mlx`, построенный индекс и `LAB_LLM_API_KEY` в корневом `.env` (только для
DeepSeek).

```sh
env -u LAB_LLM_API_KEY node apps/host/src/app/main.ts --llm-provider local --llm-local-model qwen3.8:27b-mlx rag ask "Какие верхние уровни используются в FEOD?"
ollama ps
npm run dev -- rag citations --rag-questions-file experiments/feod-citations/questions.md
cp .local/rag/rag-citations.md experiments/feod-local-llm/rag-citations-deepseek-1.md
env -u LAB_LLM_API_KEY node apps/host/src/app/main.ts --llm-provider local --llm-local-model qwen3.8:27b-mlx rag citations --rag-questions-file experiments/feod-citations/questions.md
cp .local/rag/rag-citations.md experiments/feod-local-llm/rag-citations-local-1.md
```

Первая команда прогревает модель, две последние пары повторяются по три раза (`-2`, `-3`). `npm run dev` подгружает ключ из
`.env`, поэтому локальные прогоны запускаются напрямую через `node` без `LAB_LLM_API_KEY`. Все шесть команд завершились кодом 0.
Переписанные запросы и ответы недетерминированы, повтор даст другие числа. Фрагменты документации FEOD в отчётах —

## Ручная оценка

Черновик агента, требует подтверждения автором. Шкала та же, что в [feod-citations](../feod-citations/README.md): «подтверждается» —
ответ соответствует «Ожиданию» и опирается на найденные дословно цитаты; «частично» — часть утверждений не покрыта цитатами,
цитата не несёт основного утверждения или в ответе нет элемента «Ожидания»; «не подтверждается» — ответ противоречит
цитатам или опирается на непроверенные цитаты. Для отказов: «отказ верен» или «ложный отказ». Оценка поставлена по тексту ответов и
таблицам отчётов; тексты фрагментов в `index.json` для этого эксперимента заново не перечитывались, содержание цитат смотрелось
выборочно (q06). Отказы по q10, q14, q15 верны: в корпусе нет `React`, `Redux`, `Zustand`, `MobX`, `Jest`, `Vitest` (поиск без
учёта регистра по `.local/rag/corpus`).

## Выводы

Это три прогона одной локальной модели и одной облачной на 10 вопросах и оценки одного рецензента; ниже — то, что следует из
чисел и оценок выше.

1. **Качество.** По формальным метрикам DeepSeek чище: источник и дословная цитата у 7 из 7 положительных вопросов во всех трёх
   прогонах, 70 из 70 цитат найдены, ответов без замечаний 29 из 30. У локальной модели источник есть у 20 из 21 положительных
   ответов, цитата — у 19 из 21, дословно найдены 60 из 66 цитат (90,9 %), без замечаний 26 из 30, один ложный отказ (q04, прогон 2).
   По ручной оценке смысл ответов локальной модели совпадает с «Ожиданием» почти везде, но доказательность слабее (12 против 18
   «подтверждается» из 21), а на q08 она каждый раз опускает «отдельная методология, а не переименование». Выдуманных версий и
   рекомендаций на отрицательных вопросах нет ни у одной модели.
2. **Скорость.** Локальная модель медленнее: прогон занимает 122.9–149.5 с против 29.6–30.2 с, медиана генерации 13.8–16.6 с
   против 1.9–2.1 с (примерно в 8 раз). Только переписывание запроса у неё быстрее по медиане (0.8–0.9 с против 1.1–1.4 с):
   максимум у неё выше (2.4 с против 1.7–1.9 с). Весь прогон на 10 вопросах помещается в 2–2,5 минуты;
   максимум одного вопроса 29.7 с далёк от таймаута 180 с.
3. **Стабильность.** Ошибок модели нет ни в одном из 60 вопросов, поэтому устойчивость к сбоям на этих прогонах не проверена —
   только ручной прогон с укороченным таймаутом (см. «Ограничения»). Воспроизводимость исхода у DeepSeek полная (10 из 10
   вопросов с тем же исходом и той же причиной отказа во всех трёх прогонах, длительность в пределах 2 %), у локальной
   модели слабее: 9 из 10 по исходу, 7 из 10 по причине отказа, длительность прогона отличается на 22 % (122.9 → 149.5 с), число
   цитат — 16–26 против 20–29. Переписанные запросы локальной модели различаются между прогонами («версия React FEOD requisito»
   в local-1, «React версия FEOD» в local-3 для q14; «импорт страниц rules» в local-2 для q04), от них зависят сходство и то,
   пройдёт ли вопрос порог (q10, q14); связь с ложным отказом по q04 не доказана.

**Полностью локальный режим работает.** Три прогона без `LAB_LLM_API_KEY` (запуск через `env -u` и прямой `node`, `.env` не
читается) завершились кодом 0, в шапке отчётов `local · qwen3.8:27b-mlx`. Сетевая изоляция не проверялась: отсутствие облака
подтверждено отсутствием ключа, а не отключением сети.

## Ограничения

- 10 вопросов (7 положительных, 3 отрицательных), 3 прогона на провайдера, одна машина и одна локальная модель; разброс по трём
  прогонам не позволяет оценивать вероятности.
- Температура не задавалась: у каждого провайдера своё значение по умолчанию, различия в разбросе могут частично объясняться им.
- Время — один локальный прогон на машине с Ollama; локальные прогоны шли подряд после DeepSeek, фоновая нагрузка не измерялась.
  Фактический CONTEXT 32768, а не 16384 из условий задания.
- Метрики цитат формальные: дословность проверяет подстроку, а не смысл. Ручная оценка — один рецензент (агент), тексты
  чанков не перечитывались.
- Ошибки модели в этих прогонах не возникали, поэтому поведение отчёта при сбоях проверено только тестами и отдельным ручным прогоном
  с `--llm-local-timeout-ms 1000` (не входит в измерения): 10 из 10 вопросов — «ошибка `MODEL_FAILURE`» примерно за 1,0 с
  (падает уже rewrite), отчёт записан, код 0; `rag eval` в тех же условиях прерывается с кодом 1, как раньше.
- Вопросы входят в [feod-retrieval](../feod-retrieval/README.md); q02–q08 и q10 использовались при калибровке порога 0.55.

## Что не проверено

- Другие локальные модели, температура, режимы поиска, `rag eval` и `rag dialog` на локальной модели.
- Токены в секунду и стоимость: `ModelPort` их не возвращает.
