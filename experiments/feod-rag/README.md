# Первый RAG-запрос на документации FEOD: ответы без RAG и с RAG

Второе задание недели RAG: 10 контрольных вопросов ([questions.md](questions.md)) задаются DeepSeek дважды — без поиска
и с фрагментами документации из `index.json`. Раздел «Измерения» — вывод `rag eval` без правок; «Оценка качества» и
«Выводы» — оценки, они опираются на измерения и отделены от них. Решение — [ADR 0003](../../docs/adr/0003-first-rag-query.md).

**Оценки качества — черновик, требуют подтверждения автором.** Их поставил агент-кодер по ответам из
[rag-eval.md](rag-eval.md); шкала и комментарии ниже, спорные случаи стоит перечитать.

## Воспроизведение

Нужны запущенная Ollama с `bge-m3` ([docs/ollama.md](../../docs/ollama.md)), индекс и `LAB_LLM_API_KEY` в корневом `.env`.

```sh
npm run corpus:feod
ollama pull bge-m3
npm run dev -- rag index
npm run dev -- rag eval
cp .local/rag/rag-eval.md experiments/feod-rag/rag-eval.md
```

Индекс `rag index` при повторном построении даст другое время создания и время эмбеддингов, но те же чанки. Ответы
DeepSeek при повторе будут отличаться.

([LICENSE](https://github.com/feod-architecture/feod-docs/blob/f00eaf533cfee37f67e118c96291d535b0895a6f/LICENSE)).

## Оценка качества

Шкала: «верно» — есть все пункты ожидания; «частично» — часть пунктов или есть неверная деталь; «неверно» — противоречит
ожиданию или выдумано. Для q10 «верно» — прямо сказано, что в документации этого нет.

| Вопрос | Без RAG | С RAG | Комментарий |
|---|---|---|---|
| q01 | неверно | верно | Без RAG модель не знает FEOD и гадает: FEAF, «внутренняя аббревиатура». С RAG — расшифровка, модули, public API, фрактальность, зависимости |
| q02 | неверно | верно | Без RAG — выдуманные «верхние уровни» системной декомпозиции. С RAG — все пять уровней и запрет на дополнительные |
| q03 | неверно | верно | Без RAG — ответ про переменные, ОС и Git, не про FEOD. С RAG — весь список разрешённого и запрещённого |
| q04 | неверно | верно | Без RAG — правила импортов Next.js pages router. С RAG — `modules` и `common` разрешены, запреты перечислены полностью; в конце лишний раздел «Чего во фрагментах нет» |

## Выводы

Это оценки по одному прогону и одному корпусу.

1. **RAG заметно улучшил ответы.** В 9 из 10 вопросов ответ с RAG полный. Без RAG модель не знает FEOD: в 7 вопросах из 10
   она отвечает про другое (FEAF, Front-End Operations Dashboard, системная декомпозиция, Next.js, переменные и Git, FSD),
   в остальных трёх даёт общие слова про модули и API-клиенты без правил FEOD.
2. **Отрицательный контроль сработал.** На q10 с RAG модель прямо сказала, что во фрагментах нет ответа, и не назвала
   библиотеку; без RAG она перечислила популярные менеджеры состояния. Сходство лучшего фрагмента для q10 — 0.536, ниже,
   чем у первого фрагмента любого вопроса с ответом в корпусе (0.652–0.730). Порог по этому признаку не проверялся:
   отрицательный вопрос один, а модель отказалась от ответа сама, без порога.
3. **Поиск нашёл 13 ожидаемых источников из 16, и промахи были заметны в ответах.** Не попали `guides/where-to-place-code.md`
   (q07), `guides/migration-from-fsd.md` (q08) и `get-started/faq.md` (q09). На q09 из-за этого ответ с RAG неполный:
   FAQ с нужной последовательностью шагов в top-5 не вошёл, а вошли `import-matrix.md`, `terms.md` и другие страницы про
   deep import. Ответ с RAG на q07 всё же верен, потому что `faq.md` (ранг 1) содержит ответ целиком.
4. **Модель добавляет лишнее, когда фрагменты шире вопроса.** На q04 и q08 в конце появились абзацы «Чего во фрагментах нет»
   и «Связанное уточнение» про DDD entity. Инструкция `prompts/answer.md` этого не запрещает; это шум, а не ошибка.
5. **Ссылки «Фрагмент N» появились сами.** Инструкция не требует цитат, но в q05, q06, q09 модель называет номера
   фрагментов. Это не то же самое, что проверяемые цитаты со ссылкой на источник: диапазоны и `chunk_id` она не приводит.
6. **Время.** Сумма без RAG — 30.6 с, с RAG — 20.7 с; с RAG быстрее в 9 вопросах из 10 (q08 — 2.0 против 2.8 с). Причина не
   исследовалась: длина ответов не измерялась, прогон один. Размер контекста с RAG — от 3 983 до 6 065 символов.

## Что не проверено

- Разброс между прогонами: DeepSeek недетерминирован, прогон один; температура не задавалась.
- Другие значения top-K и стратегия `fixed`: сравнение стратегий в `rag eval` не входит; q09 указывает, что top-5 может быть мало.
- Порог релевантности, реранкинг, переписывание запроса — следующие задания.
- Оценки качества поставил один рецензент по шкале выше; независимой второй оценки нет.
- Ответы без RAG зависят от знаний модели о FEOD; было ли содержимое корпуса в её обучающих данных — не проверялось.
