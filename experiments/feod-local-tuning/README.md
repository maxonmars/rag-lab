# Оптимизация локальной модели под RAG: параметры, контекст и шаблон ответа

Задание восьмого дня недели RAG: настроить локальную модель `qwen3.8:27b-mlx` под RAG по документации FEOD и сравнить её «до» и
«после» по качеству, скорости и ресурсам ([ADR 0008](../../docs/adr/0008-local-llm-tuning.md)). Конвейер тот же, что в
[feod-local-llm](../feod-local-llm/README.md): rewrite запроса, поиск, отбор по порогу, ответ с источниками и цитатами. Приоритет —
качество при той же скорости: дословность цитат и доказательность ответов, медиана генерации не должна вырасти. Три конфигурации по
3 прогона `rag citations` на 10 вопросах ([../feod-citations/questions.md](../feod-citations/questions.md)): 7 положительных и 3
отрицательных (q10, q14, q15). Демо — [docs/demos/local-tuning.md](../../docs/demos/local-tuning.md).

Разделы «Условия прогона» и «Измерения» — вывод `rag citations` и системных команд (девять отчётов рядом); «Вычислено по отчётам» —
арифметика над ними; «Ручная оценка» и «Выводы» — оценки, они опираются на измерения и отделены от них.

**Ручная оценка — черновик агента, требует подтверждения автором.**

## Воспроизведение

Нужны запущенная Ollama с `bge-m3`, `qwen3.8:27b-mlx` и `rag-local` (из [feod-local-llm](../feod-local-llm/README.md)) и
построенный индекс.

```sh
ollama create rag-local-opt -f experiments/feod-local-tuning/Modelfile
ollama show rag-local-opt --parameters
```

Для каждой конфигурации (`<M>`/`<P>`: base — `rag-local`/`default`, params — `rag-local-opt`/`default`, tuned —
`rag-local-opt`/`compact`) перед сменой модели выгружались предыдущие (`ollama stop <модель>`):

```sh
npm run dev:local -- --llm-local-model <M> --rag-answer-prompt <P> rag ask "Какие верхние уровни используются в FEOD?"
ollama ps
curl -s http://localhost:11434/api/generate -d '{"model":"<M>","prompt":"Перечисли пять уровней FEOD и кратко опиши каждый.","stream":false,"think":false,"options":{"num_predict":256}}'
npm run dev:local -- --llm-local-model <M> --rag-answer-prompt <P> rag citations --rag-questions-file experiments/feod-citations/questions.md
cp .local/rag/rag-citations.md experiments/feod-local-tuning/rag-citations-<base|params|tuned>-<n>.md
```

Последняя пара команд повторялась по три раза (`-1`, `-2`, `-3`). Прогревы и все девять прогонов `rag citations` завершились кодом 0. Скорость вывода без RAG
измерена запросом к `/api/generate` с `num_predict` 256, а не `ollama run --verbose`: без RAG модель не знает FEOD и генерирует
без ограничения длины. Поля ответа — `prompt_eval_count`, `prompt_eval_duration`, `eval_count`, `eval_duration` — те же, что печатает
`--verbose`. Переписанные запросы и ответы недетерминированы, повтор даст другие числа. Фрагменты документации FEOD в отчётах —
Copyright (c) 2026 FEOD Architecture, лицензия MIT
([LICENSE](https://github.com/feod-architecture/feod-docs/blob/f00eaf533cfee37f67e118c96291d535b0895a6f/LICENSE)).

## Ручная оценка

Черновик агента, требует подтверждения автором. Шкала на основе [feod-citations](../feod-citations/README.md): П — «подтверждается»:
ответ соответствует «Ожиданию» и все цитаты найдены дословно, замечаний нет; Ч — «частично»: основное утверждение подтверждено, но в
ответе нет элемента «Ожидания» либо есть замечание (ненайденная цитата, цитата короче 20 символов, лишние разделы); НП — «не
подтверждается»: основное утверждение держится только на ненайденных цитатах. Для отказов: ОВ — отказ верен. Оценка поставлена по
тексту ответов и таблицам отчётов, элементы «Ожидания» проверялись по ключевым словам и чтением; тексты фрагментов в `index.json`
заново не перечитывались. Отказы по q10, q14, q15 верны: в корпусе нет `React`, `Redux`, `Zustand`, `MobX`, `Jest`, `Vitest`
(проверка из [feod-local-llm](../feod-local-llm/README.md)); во всех 27 отказах ответа по существу нет, исход — «не знаю» с уточняющим вопросом.

## Выводы

Это три прогона на конфигурацию, 10 вопросов и оценки одного рецензента; ниже — наблюдения, а не вероятности. Разброс внутри
конфигурации (например, 14–19 цитат у base, 74–93 % дословных цитат по прогонам у tuned) сопоставим с эффектами.

1. **Вклад параметров (base → params).** Лучший результат из трёх: дословных цитат 60 из 63 (95,2 %) против 45 из 52 (86,5 %),
   ответов без замечаний 26 из 30 против 22 из 30, у каждого положительного вопроса в каждом прогоне есть дословная цитата (21 из
   21 против 20 из 21). Средняя медиана генерации ниже на 21 %, скорость вывода без RAG та же (26,9 и 26,8 токенов/с). Изменены
   два параметра сразу (temperature 1 → 0.2 и `num_ctx` 32768 → 16384), поэтому вклад каждого из них отдельно не измерен;
   `num_ctx` на скорость вывода не повлиял, а SIZE в `ollama ps` не уменьшился (19 ГБ у обеих).
2. **Вклад шаблона (params → tuned).** Шаблон `compact` ухудшил дословность: 59 из 70 (84,3 %) против 60 из 63 (95,2 %), без
   замечаний 25 из 30 против 26 из 30, «не подтверждается» 2 против 0. Ответы стали полнее — больше источников и цитат на вопрос
   (70 цитат против 63; q03 — по 5 источников), но модель не выполняет заданные правила: в q06 (t-1) вставляет «…» в цитаты
   таблицы, в q02 (t-3) обрывает цитату на открытой обратной кавычке, в q04 (t-2) выводит рассуждения в раздел «Цитаты». Правила «не
   склеивай», «без многоточий», «копируй ячейку без `|`» не снизили число ненайденных цитат; рост числа цитат увеличил число
   возможностей ошибиться.
3. **Скорость и ресурсы.** Скорость вывода без RAG: 26,8 / 26,9 / 24,6 токенов/с (base / params / tuned), веса одни и те же, а
   отставание tuned на 8 % получено одиночным замером и не повторялось. Медиана генерации у tuned ниже base на 18 %, но длительность
   прогона выше на 9 %. Память: SIZE 19 ГБ у всех конфигураций, `num_ctx` 16384 вместо 32768 в `ollama ps` ничего не уменьшил.
4. **Решение о профиле.** Критерий из плана (tuned против base): суммарная доля дословных цитат не ниже — **не выполнен**
   (84,3 % против 86,5 %); ответов без замечаний не меньше — выполнен (25 против 22); ложных отказов не больше — выполнен (0 и 0);
   средняя медиана генерации не больше чем на 10 % — выполнен (ниже на 18 %). Критерий не выполнен, поэтому tuned в профиль не включён. Отрицательный результат шаблона `compact` на этих вопросах: параметры модели
   помогли, шаблон — нет. Конфигурация params (`rag-local-opt` + `default`) критерий выполняет по всем четырём пунктам (95,2 % против 86,5 %, 26 против 22,
   0 и 0, медиана ниже на 21 %), поэтому по решению автора `lab.local.yaml` переключён на неё: `llm.localModel: rag-local-opt`,
   шаблон — по умолчанию.

## Ограничения

- 10 вопросов (7 положительных, 3 отрицательных), 3 прогона на конфигурацию, одна машина; разброс по трём прогонам не позволяет
  оценивать вероятности. Прогоны шли подряд в фиксированном порядке (base, params, tuned), порядок и нагрев машины не
  рандомизировались.
- Temperature не перебиралась (одно значение 0.2); вклады temperature и `num_ctx` в params не разделены.
- Квантование не сравнивалось (см. ниже), `llm.maxOutputTokens` не менялся.
- Токены и потребление на RAG-запросе не измерялись (`ModelPort` их не возвращает); скорость вывода — одиночный замер без RAG на
  коротком промпте (26 токенов), не на реальном сообщении RAG.
- `rag dialog` и REPL-чат на `rag-local-opt` не прогонялись: достаточность `num_ctx` 16384 для истории в 6 ходов не проверена;
  обрезка контекста подтверждена только косвенно.
- Шаблон `compact` проверялся на тех же вопросах, по которым видны сбои base; правила в нём общие, содержание FEOD в промпт не вписано.
- Метрики цитат формальные: дословность проверяет подстроку, а не смысл. Ручная оценка — один рецензент (агент).
- Вопросы входят в [feod-retrieval](../feod-retrieval/README.md); q02–q08 и q10 использовались при калибровке порога 0.55.

## Квантование

Текущие веса `qwen3.8:27b-mlx` — `27b-nvfp4`, 27,8B, 18 ГБ, уже 4-битное квантование MLX; оно зафиксировано и не менялось, новые веса
не скачивались. Альтернативы из реестра Ollama, согласно плану задания, не проверялись и в этой сессии не запускались: `27b-mxfp8`
(32 ГБ), `27b-q4_K_M` (18 ГБ), `27b-q8_0` (30 ГБ); размеры взяты из плана, на реестре заново не сверялись.

## Почему `llm.maxOutputTokens` не менялся

Лимит не укорачивает ответ: при `finish_reason: length` адаптер возвращает `AgentError INCOMPLETE_RESPONSE`, и вопрос остаётся без
ответа. Длину ответа регулирует промпт. В прогонах ошибок модели 0 из 90, лимит 1024 не достигался.
