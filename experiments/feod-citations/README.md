# Источники, цитаты и «не знаю» на документации FEOD

Четвёртое задание недели RAG: модель отвечает с источниками и цитатами, код проверяет, что каждая цитата дословно есть в
указанном фрагменте, а при пустом контексте после отбора по порогу ассистент отвечает «не знаю» без вызова модели.
10 вопросов ([questions.md](questions.md)): 7 положительных и 3 отрицательных, скопированы из
[feod-retrieval](../feod-retrieval/questions.md) без изменений. Разделы «Условия прогона» и «Измерения» — вывод
`rag citations` ([rag-citations.md](rag-citations.md)) и вычисления по нему, помеченные как вычисленные; «Ручная оценка» и
«Выводы» — оценки, они опираются на измерения и отделены от них. Решение — [ADR 0005](../../docs/adr/0005-citations-and-refusal.md),
демо — [docs/demos/citations.md](../../docs/demos/citations.md).

**Ручная оценка — черновик, требует подтверждения автором.** Её поставил агент-кодер по ответам из [rag-citations.md](rag-citations.md)
и текстам процитированных чанков в `index.json`; шкала и комментарии ниже, спорные случаи стоит перечитать.

## Воспроизведение

Нужны запущенная Ollama с `bge-m3` ([docs/ollama.md](../../docs/ollama.md)), индекс и `LAB_LLM_API_KEY` в корневом `.env`.

```sh
npm run corpus:feod
ollama pull bge-m3
npm run dev -- rag index
npm run dev -- rag citations --rag-questions-file experiments/feod-citations/questions.md
cp .local/rag/rag-citations.md experiments/feod-citations/rag-citations.md
```

Индекс при повторном построении даст другое время создания, но те же чанки. Переписанные запросы и ответы DeepSeek при повторе
будут отличаться, а вместе с ними и набор переданных фрагментов.

Фрагменты документации FEOD в отчёте — Copyright (c) 2026 FEOD Architecture, лицензия MIT
([LICENSE](https://github.com/feod-architecture/feod-docs/blob/f00eaf533cfee37f67e118c96291d535b0895a6f/LICENSE)).

## Ручная оценка

Шкала для ответов: «подтверждается» — каждое утверждение ответа опирается на дословную цитату или текст указанного фрагмента;
«частично» — часть утверждений не покрыта цитатами, или цитата вырвана из контекста; «не подтверждается» — ответ противоречит
цитатам или опирается на непроверенные цитаты. Цитата без содержания (заголовок таблицы, вводная строка списка) считалась
вырванной из контекста, если ни одна цитата ответа не несёт его основное утверждение. Для отказов: «отказ верен» или «ложный отказ».
Тексты фрагментов сверялись по `index.json`; в корпусе нет `React`, `Redux`, `Zustand`, `MobX`, `Jest`, `Vitest`
(поиск без учёта регистра по `.local/rag/corpus`), поэтому отказы по q10, q14, q15 верны.

## Выводы

Это один прогон одной модели на одном корпусе и оценки одного рецензента; ниже — только то, что следует из чисел и оценок выше.

1. **Формат ответа выдержан во всех ответах.** 7 из 7 положительных ответов содержат источник и цитату, 17 из 17 цитат найдены
   дословно, замечаний к контракту нет ни у одного из 10 ответов. Повторный вызов модели не понадобился, и одним прогоном
   частоту нарушений формата не оценить.
2. **Дословность цитаты не равна подтверждению смысла.** Проверка замечаний не дала, но в q06 цитата — заголовок таблицы, а в
   q02 и q03 две из трёх цитат — вводные строки списков. Ручная оценка 6 / 1 / 0 нашла то, чего механическая проверка не видит:
   `MIN_QUOTE_CHARS` отсекает слишком короткие цитаты, но не бессодержательные длинные.
3. **Отказ по пустому контексту сработал на q10 и q15 без вызова модели.** Лучшее сходство 0.520 и 0.478 ниже порога 0.55; генерации
   нет, ответ называет порог. В [feod-retrieval](../feod-retrieval/README.md) q10 в режиме `rewrite-filter` при пустом контексте получил выдуманный
   ответ «по общим знаниям»; при пустом контексте теперь модель не вызывается, и такой ответ невозможен по построению. Попадание q10 под порог зависит от переписанного запроса: запас
   0.030 (q10) и 0.072 (q15).
4. **Порог не отделяет все отрицательные вопросы от положительных.** Лучшее сходство q14 (0.583) выше, чем у положительного q06
   (0.564): порог, который отсёк бы q14, потерял бы q06. На q14 модель отказала сама, но по одному прогону надёжность такого
   отказа не оценить: в feod-retrieval q14 тоже прошёл порог и тоже не получил выдуманной версии, но инструкция тогда
   не запрещала общие знания.
5. **Отказ по порогу дешевле ответа.** q10 и q15 заняли 1.0 и 0.8 с (rewrite и поиск), остальные вопросы — 2.1–4.5 с; на каждом
   отказе по порогу экономится вызов генерации.

## Ограничения

- Один прогон, 10 вопросов (7 положительных, 3 отрицательных), один корпус, одна модель ответов; DeepSeek недетерминирован
  (температура не задавалась), разброс между прогонами не измерен.
- Нормализация цитаты уравнивает регистр, «ё», пробелы, Markdown-символы, тире и кавычки; перефразирование она не распознаёт, а
  найденная цитата не доказывает, что ответ ей следует.
- Ссылки `[N]` внутри текста ответа не проверяются (в q07 первое предложение без ссылки); проверяются только разделы «Источники»
  и «Цитаты». Позиция цитаты в документе (`start`–`end`) не фиксируется.
- Ручная оценка — один рецензент (агент), независимой второй оценки нет; шкала применена по тексту чанков, а не по оригинальным
  страницам FEOD.
- Все десять вопросов входили в [feod-retrieval](../feod-retrieval/README.md); q02–q08 и q10 — ещё и в набор калибровки порога 0.55,
  поэтому порог не независим от этих вопросов.
- Токены и стоимость не измерялись; время — один локальный прогон.

## Что не проверено

- Повторные прогоны и доля нарушений формата при них; другие режимы поиска (`baseline`, `filter`, `rewrite`).
- Отдельный порог отказа и его калибровка, проверка смысла LLM-судьёй, проверка inline-ссылок и позиции цитаты — за пределами задания.
