# Фича rag: индексация, поиск, отбор по порогу и ответ с RAG

Читает Markdown-корпус, режет его двумя стратегиями, получает эмбеддинги через Ollama и сохраняет `index.json`.
Отчёт сравнения стратегий читает индекс. Поиск находит кандидатов по вопросу, второй этап отбирает их по порогу
сходства, `answerWithRag` склеивает итоговые чанки с исходным вопросом в Markdown и отправляет модели. Запрос для
поиска можно переписать моделью. `calibrateThreshold` подбирает порог, `evaluateQuestions` сравнивает четыре режима.
Решения — [ADR 0002](../../../../../docs/adr/0002-document-indexing.md) (индексация),
[ADR 0003](../../../../../docs/adr/0003-first-rag-query.md) (RAG-запрос) и
[ADR 0004](../../../../../docs/adr/0004-relevance-filter-and-query-rewrite.md) (порог, rewrite, калибровка, сравнение).

## Публичный контракт (`index.ts`)

- `indexCorpus(options)` — корпус → чанки `fixed` и `structure` → эмбеддинги → `index.json`. Индекс заменяется целиком
  после успеха всех запросов; при ошибке прежний файл остаётся. Возвращает счётчики, токены и время по стратегиям.
- `compareIndex({ indexFile, reportFile })` — читает индекс и пишет `comparison.md` без обращения к модели.
- `openIndex({ indexFile, embeddings })` — читает индекс один раз и проверяет digest модели эмбеддингов; возвращает
  `SearchIndex` с `search(question, strategy, topK)`: эмбеддинг вопроса → косинусная близость по чанкам одной
  стратегии → `SearchHit[]` (`rank` с 1, `score`, чанк без вектора).
- `answerWithRag({ question, index, strategy, mode, candidateTopK, topK, threshold, model, systemPrompt })` — rewrite
  (по режиму) → поиск `candidateTopK` кандидатов → отбор → ответ `Agent`; системная инструкция вызывающего дополняется
  `prompts/answer.md`. Пустой вопрос — `AgentError EMPTY_INPUT`, несогласованные параметры — `INVALID_RETRIEVAL_PARAMS`,
  оба до rewrite и поиска. Возвращает `answer`, итоговые `hits`, `contextChars`, фактическую строку поиска `query`,
  исходные `candidates` и длительности этапов `timings` (`rewriteMs`, `searchMs`, `selectMs`, `generateMs`).
- `RETRIEVAL_MODES` (`baseline`, `filter`, `rewrite`, `rewrite-filter`), `RetrievalMode`, `checkRetrievalParams(params)`,
  `MAX_TOP_K`, `SIMILARITY_RANGE`, `usesFilter(mode)` — единый набор режимов и единственная проверка параметров.
- `calibrateThreshold(options)` — один поиск исходной формулировкой на вопрос, сетка порогов, `rag-calibration.md`;
  модель генерации не нужна.
- `evaluateQuestions(options)` — читает контрольные вопросы, для каждого запускает все четыре режима на общих кандидатах,
  считает метрики и пишет `rag-eval.md`; первая ошибка прерывает прогон, отчёт не пишется.
- `EmbeddingPort` — `embed(texts)` (векторы, `prompt_eval_count` и `load_duration` пакета) и `describeModel()`.
- `createOllamaEmbeddings(options)` — адаптер Ollama `/api/embed` и `/api/tags` с внедряемым `fetch`.
- `RagError`, `describeRagError` — типизированные ошибки и русские сообщения для CLI.

## Режимы поиска и отбор

| Режим | Строка поиска | Порог |
|---|---|---|
| `baseline` | исходный вопрос | нет |
| `filter` | исходный вопрос | да |
| `rewrite` | переписанный запрос | нет |
| `rewrite-filter` | переписанный запрос | да |

Поиск (`SearchIndex.search`) остаётся низкоуровневым: он возвращает `candidateTopK` кандидатов по убыванию сходства.
Отбор — отдельная чистая функция над готовым списком: при фильтре оставляет `score >= порог`, затем берёт первые
`topK`; порядок и score не меняются, дубликаты файлов не убираются, чанки ниже порога не добираются. Отдельно считаются
кандидаты, удалённые порогом, отброшенные конечным K и переданные модели. Фильтр не реранжирует: он удаляет слабый хвост.
Кандидаты отсортированы, поэтому итог — префикс списка, и `candidateTopK` > `topK` сам по себе не меняет выдачу
threshold-фильтра. Параметры проверяются до внешних вызовов: оба K — целые от 1 до 20, `topK` ≤ `candidateTopK`, порог
— число от −1 до 1.

**Переписывание запроса.** Один вызов `Agent` с инструкцией `prompts/rewrite.md`, без истории и инструментов; в генерацию
всегда идёт исходный вопрос. Ответ должен быть одной строкой: несколько строк или Markdown-забор — `REWRITE_INVALID`,
пустой ответ — `AgentError EMPTY_RESPONSE`. Запрос не извлекается из произвольного ответа, вызов не повторяется, исходный
вопрос скрыто не подставляется.

**Пустой контекст.** Если отбор ничего не оставил, модель всё равно отвечает: в сообщении нет фрагментов, инструкция
`prompts/answer.md` велит сказать об этом. CLI показывает «Фрагменты: контекст пуст» — это не утверждение об отсутствии
ответа в корпусе.

**Калибровка.** `rag calibrate` проверяет пороги 0.50, 0.55, 0.60, 0.65 на общих кандидатах. Baseline — первые `topK`
кандидатов без порога. Выбор — лексикографический максимум: сохранённые уникальные пары «вопрос — ожидаемый файл», затем
число отрицательных вопросов с пустым итоговым контекстом, затем порог. Потеря источника не компенсируется отсечением
отрицательного вопроса; считается по точным score.

**Сравнение режимов.** На вопрос — исходный поиск (baseline, filter), один rewrite и один поиск переписанной строки
(rewrite, rewrite-filter): два поиска, один rewrite, четыре генерации. Метрики по итоговым hits: hit@K, MRR и покрытие
источников — по положительным вопросам, доля непустого контекста — по отрицательным; пустой знаменатель — «—». Время
режима — сумма его этапов (общие этапы входят в оба режима пары), фактическая длительность прогона — отдельно.

## Формат `index.json` (`formatVersion: 1`)

| Поле | Содержимое |
|---|---|
| `createdAt`, `corpusHash` | время построения; sha256 от списка файлов и хешей их текста |
| `params` | `chunkSizeChars`, `overlapChars`, `minChunkChars` |
| `model`, `modelLoadMs` | `name`, `digest`, `dimension`; `load_duration` прогрева |
| `documents[]` | `file`, `source`, `title`, `hash`, `text` (нормализованный), `blocks[]` (`type`, `start`, `end`, `section`) |
| `strategies.fixed`, `strategies.structure` | `chunkingMs`, `embeddingMs`, `promptTokens`, `chunks[]` |
| `chunks[]` | `chunk_id`, `strategy`, `source`, `title`, `file`, `sections[]`, `start`, `end`, `text`, `embedding` |

Диапазоны `start`–`end` — кодовые точки Unicode: `text` равен срезу `documents[].text` по диапазону.

## Сообщение в режиме RAG

Пользовательское сообщение собирает `renderRagMessage` как Markdown; инструкции модели в нём нет, они в `prompts/answer.md`:

````text
## Фрагменты документации

### Фрагмент 1

- Файл: `structure/global.md`
- Документ: Global
- Разделы: Global › Правило; Global › Почему

```markdown
<текст чанка как есть>
```

## Вопрос

<вопрос>
````

Забор длиннее любой серии обратных кавычек в тексте чанка. Сходство и URL источника модели не передаются. Без фрагментов
остаются заголовок «Фрагменты документации» и вопрос.

## Контрольные вопросы

Файл `experiments/feod-retrieval/questions.md`: раздел `## qNN. Вопрос`, строки `Ожидание:` и `Источники:` (файлы корпуса
через запятую, `—` — ответа в корпусе нет; такой вопрос отрицательный). Ошибки формата — `QUESTIONS_INVALID` с причиной;
источник, которого нет в индексе, отклоняется до первого поиска и вызова модели. Отчёт `rag-eval.md` содержит сводку
режимов, исходный и переписанный запрос, кандидатов со scores и причиной исключения, ответы всех режимов и время этапов;
оценки качества в него не входят.

## Настройки и команды

`rag.inputDir`, `rag.outputDir`, `rag.chunkSizeChars` (1800), `rag.overlapChars` (200, строго меньше размера),
`rag.minChunkChars` (500, не больше размера), `rag.embeddingBaseUrl`, `rag.embeddingModel` (`bge-m3`),
`rag.embeddingTimeoutMs`; для поиска — `rag.chunkStrategy` (`structure`), `rag.retrievalMode` (`rewrite-filter`),
`rag.candidateTopK` (10), `rag.topK` (5, не больше `rag.candidateTopK`; оба от 1 до 20), `rag.similarityThreshold`
(0.55, от −1 до 1), `rag.questionsFile`. Полный список — [docs/configuration.md](../../../../../docs/configuration.md).
Команды: `rag index`, `rag compare`, `rag calibrate`, `rag ask`, `rag on`, `rag off`, `rag eval` —
[docs/commands.md](../../../../../docs/commands.md).

## Ограничения

- Размеры в кодовых точках, не в токенах; токены известны только суммой на стратегию (по пакетам из 8 текстов).
- Frontmatter и переводы строк нормализуются; только `.md`, без PDF и TXT.
- Блок длиннее лимита в `structure` делится окнами как в `fixed`; такие блоки видны в метрике разорванных блоков.
- Время — один локальный прогон после прогрева.
- Поиск — линейный перебор; порог 0.55 привязан к модели эмбеддингов `bge-m3` и корпусу FEOD, сетка калибровки — четыре значения.
- Индекс читается целиком на каждый `rag ask`; при другой модели эмбеддингов (digest) поиск отказывается работать.
- Метрики считаются по файлам итоговых чанков: это не оценка релевантности чанков и не качество ответа; уменьшение
  контекста не доказывает улучшение ответа. Rewrite может изменить смысл запроса.
- `rag eval` — один прогон, DeepSeek недетерминирован; разброс между прогонами не измерен. `rag calibrate` работает на
  одном наборе вопросов и одном корпусе. Токены и стоимость не считаются: `ModelPort` их не возвращает.
- Специализированного реранкинга, истории диалога, цитат и режима отказа нет.
